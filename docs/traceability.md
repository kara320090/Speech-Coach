# 현재 요구사항·구현·검증 연결

현재 제출의 기준은 [problem.yaml](problem.yaml)과 [scenarios.yaml](scenarios.yaml)이다. 종이의 문제·고객·E1·E2·5 Whys와 기존 출처를 보존하고 현재 구현의 완료 조건을 연결한다.

## 선택 해법 네 경로

| 선택 경로 | 끝까지 확인하는 흐름 |
| --- | --- |
| 관찰 → 상황 확인 → 조건 변경 → 구간 재연습·비교 | S5·S9 |
| 개념·자기 설명·쉬운 대본·자료 기반 질문 | S8 |
| 시간·구간 계획 안내 | S1·S2·S3 |
| 영상·소리 기록·검토·같은 조건 비교 | S4·S6 |

## 제출 시나리오

| ID | 결과 | 기능 |
| --- | --- | --- |
| S1 | 목표보다 일찍 종료 | F1·F2 |
| S2 | 목표 시간 초과 | F2 |

| S6 | 실제 영상 파일 → 실제 AI 전사·속도 집계 + 로컬 MediaPipe | F4·F16·F21 |

S5·S8은 실제 텍스트 AI, S6는 실제 음성 전사와 브라우저 MediaPipe를 사용한다. 모든 흐름은 처음 화면에서 시작하며 다른 흐름의 데이터를 전제로 하지 않는다. 초기 화면은 스튜디오이고 기존 시간 연습은 `/#/`로 보존한다.

## 검증 경계

채점용 `e2e/scenarios/`에는 고정 AI 응답·조건부 종료·가상 장치 설정을 두지 않는다. `e2e/media/S7-real-recording.spec.ts`는 원본 촬영 파일을 가상 장치로 재생하는 별도 증빙이며 실제 Gateway를 호출한다. 같은 입력 재생의 전후 값으로 이해·발표 개선을 확정하지 않는다.

기본 Docker는 모델을 내려받지 않는 Node 서버와 Gateway 설정이다. 자체 공개 모델의 실행·배포는 운영 모드와 별도 모델 Docker의 범위다. 생성·분석·전사 모두 실제 공급자·처리 위치를 화면에 표시한다.

source ID는 R1–R11이며 기존 조사 내용은 [source-records.md](source-records.md)에 보존한다. E2 직접 인용은 새 진술을 받기 전까지 null이다. 후속 시간 예측·자동 연결/4열 비교는 `solution_paths`의 보류 이유에 두고 현재 기능 번호로 재사용하지 않는다.
