# Speech-Coach 서비스 기획서

## 2026-10-30 main 통합 상태

main의 다시봄 화면, TXT 불러오기, 구간 질문·조건 선택·재연습(S9), E2와 공개 조사 기록을 보존했다. 자체 AI 대본 코칭과 선택 전사, 영상 눈 깜빡임을 함께 제공한다. main의 F15는 대본 이해 교차 확인으로 유지하고, PR #3의 눈 깜빡임은 F21로 변경했다. 기존 문서의 미구현 표시는 당시 기록이며, 현재 상태는 이 절과 구현 범위 문서를 따른다. F13–F14 기본 흐름은 구현됐지만 전체 계획 수용 조건이 검증됐다는 뜻은 아니다.

**현재 구현 상태:** 자체 실행 텍스트 코칭과 음성 전사의 첫 구현이 추가됐다. 아래 전체 기획의 완료 조건과 구현된 부분은 [구현 범위](local-ai-implementation.md)에서 구분한다. 외부 AI Gateway와 브라우저 실시간 음성 인식은 제거/비활성화했다.


기준일: 2026-10-29. 대상은 설치 없이 사용하는 PC·노트북 웹 서비스다. 새 이해·수정·질의응답 흐름은 첫 구현이 추가됐으며 전체 수용 조건은 후속 검증한다. 기반 코드는 PR #3의 F21–F16을 포함한다.

## 1. 서비스 정의

Speech-Coach는 AI가 만든 대본을 활용하는 대학생이 낯선 개념과 근거를 확인하고, 자기 말로 설명할 수 있는 표현으로 바꾸며, 예상 질문과 재연습으로 준비 상태를 점검하는 웹 서비스다. 공개 모델을 개발자 PC 또는 직접 운영하는 서버에서 실행하고, 초기에는 추가 학습 없이 프롬프트·자료 연결·검증·연습 흐름을 개발한다.

핵심 흐름: **대본·근거 자료 → 낯선 개념 후보 → 자기 말로 설명 → 쉬운 표현과 의미 보존 → 예상 질문 답변 → 재설명·전체 연습 비교**. 사용자가 원하면 곧바로 쉬운 설명을 받을 수 있다. 군말·말 더듬음·눈 깜빡임에서 이해 부족이나 감정을 판정하지 않는다.

## 2. 사용자와 과업

| 항목 | 정의 |
| --- | --- |
| 우선 대상 | AI 대본의 일부 표현·논리·근거를 자신의 말로 설명하는 연습이 필요한 대학생 |
| 사용 시점 | 자료·대본 준비 후 실제 발표·질의응답 전 |
| 사용자 입력 | 대본, 선택 근거 자료, 필수 내용, 낯선 부분, 자기 설명·답변, 선택 시간 조건 |
| 자동화 | 개념 후보·자료 위치 연결, 짧은 이해 질문, 쉬운 표현 제안, 의미 변경 경고, 예상 질문, 답변·재연습의 근거 비교 |
| 사용자 선택 | 이미 아는 표현 제외, 모름·건너뛰기·설명받기, 제안 적용·수정·되돌리기, 연습 조치 선택 |
| 산출물 | 개념별 근거 카드, 원본/쉬운 대본 버전, 자기 설명·질문 응답 기록, 도움 여부와 전후 근거 |
| 환경 | 브라우저 사용. 초기 핵심 과업은 텍스트만으로 가능. 마이크·카메라 선택 |

시간·녹음·구간 재생·회차 비교는 보조 기능으로 유지한다. 기존 F15의 눈 깜빡임 측정은 선택 측정이며 새 문제의 핵심 지표로 쓰지 않는다. 서비스 이용자에게 모델 설치·네이티브 앱 설치를 요구하지 않는다.

## 3. 문제 근거와 검증할 부분

사용자는 “AI로 만든 대본을 충분히 이해하지 못하면 어려운 단어를 읽는 모습이 어색하고, 군말이 나오거나 질문에 답하기 어렵다”는 새 방향을 제시했다. 이는 제품 문제 관찰이며 개별 사례·빈도·인과관계는 아직 검증하지 않았다. 발표자가 모두 AI 대본을 쓴다거나 모든 군말이 이해 부족에서 나온다고 일반화하지 않는다.

기존 E1은 별도로 보존한다. 사용자는 10분 이상 11분 미만이어야 하는 발표를 10분 30초 목표로 준비했고, 시간 초과·미달과 시계 확인으로 흐름이 끊기는 경험을 했다. 수동 녹음·웹캠 재생 점검이 오래 걸렸고 대사 암기 등을 포함한 준비 전반이 약 10시간이었다고 기억한다. 실제 종료 시각·감점·활동별 시간은 미확인이다. 이 시간 부담이 AI 대본 이해 부족 때문이었다고 바꾸지 않는다.

새 과업에서 확인할 것은 낯선 표현이 실제 자기 설명·질의응답에 걸림돌이 되는지, 쉬운 말과 근거 확인이 도움 없는 설명까지 이어지는지, 질문과 수정에 드는 추가 부담이 얼마나 되는지다. [캔버스](problem-canvas.md)와 [검증 계획](validation-plan.md)에 연결했다.

## 4. 차별화할 제품 과업

쉬운 문장 만들기, 질문 생성, 긍정적인 말투, 공개 모델 자체 실행 각각은 독점적인 기능으로 주장하지 않는다. 범용 AI도 대본을 수정하고 질문할 수 있고 PT샌드백에도 질의응답이 있다. 기존 조사에서 Talkli의 회차 비교와 SayNow의 성장 기록도 확인했다.

우리 설계는 **같은 개념 ID에 원문 근거·발표자의 설명·수정한 대본·질문 답변·도움 없이 다시 설명한 결과를 연결**한다. 사용자에게 대화 기록을 찾아 정리하는 일을 덜 남기는 것이 검증할 가치다. 경쟁사 전체에 이 흐름이 없다는 결론이나 효과가 더 좋다는 결과는 아직 없다. [경쟁 분석](competitive-analysis.md)에 확인/미확인을 구분한다.

긍정적 피드백은 “자료의 어떤 부분을 설명했는지 → 다음에 보완할 한 가지 → 바로 해볼 연습”으로 구성한다. 오답을 맞다고 하거나 “이해력이 부족하다”, “AI가 불안을 해결했다”라고 표현하지 않는다. 예시는 [코칭 설계](coaching-design.md).

## 5. 구현 단계와 우선순위

| 단계 | 우선 과업 | 기능 | 완료 기준 |
| --- | --- | --- | --- |
| R0 기존 연습 | 기본 연습·녹음·측정 보존 | F1–F6·F21–F16 기존 코드 | 기존 S1–S4 유지. 외부 전사와 자체 AI 계획 구분 |
| R1 텍스트 이해·수정 | 자료·버전, 개념 후보, 자기 설명, 쉬운 문장·의미 보존, 자체 모델 연결 | F7·F9–F10·F17–F18·F20 텍스트 | 한국어 실제 추론·인용·형식·자료 부족·오류·외부 호출 없음 검증 |
| R2 질의응답·재확인 | 질문과 답변, 자기 설명 전후 비교, 긍정적 피드백·연습 조치 | F19·F11·F13–F14 | 도움 여부·개념별 근거·동등 질문·질문 상한·변화 없음 확인 |
| R3 음성·시간·결과 | 자체 전사, 실측 시간 조정, 전체 연습·내보내기 | F20 전사·F16 전환·F8·F12, F9 시간 확장 | 실제 한국어 음성·구간 품질·전체 시간 검증, 외부 전사 경로 차단 |

F9는 쉬운 말 수정부터 구현하며 시간 실측이 없어도 사용할 수 있다. F20은 텍스트와 음성 전환의 완료 여부를 따로 기록한다. 단계표는 전체 목표다. 현재 자체 실행 LLM·이해 확인·쉬운 대본 수정·질문 연습·자체 전사의 초기 구현이 있으며 세부 완료 여부는 구현 범위 문서에 기록한다. 일정·담당 팀원은 임의로 정하지 않는다.

## 6. 기술·운영 결정

[자체 AI 설계·공개 프로젝트 분석](local-ai-design.md)에 실행기·모델·출처·라이선스·내부 통신·전환 순서를 적었다. llama.cpp와 공식 Qwen3-4B GGUF를 첫 검증 후보로 삼는다. 질문형 공개 튜터의 연결 구조를 참고하고, 음성은 후속 단계에서 faster-whisper를 검토한다. 초기 추가 학습은 없다.

모델은 서버에서 직접 실행한다. 자체 서버 처리에도 텍스트·선택 음성이 브라우저 밖으로 나가므로 처리 위치와 자료 범위를 안내한다. 공개 서비스에는 운영 장비·동시 요청 제한·실제 지연 검증이 필요하다. 로컬 주소를 Render에서 호출할 수 있다고 가정하지 않는다. 외부 AI 서비스 API 호출·클라우드 자동 대체는 새 방향에서 제외한다.

AI Gateway 전사 코드를 자체 worker로 대체했고 선택 브라우저 음성 인식은 비활성화했다. 코드와 테스트로 외부 제공자 호출 경로 제거를 확인했다. 실제 공개 배포의 운영 구성은 별도 검증한다.

## 7. 범위 밖

- 기반 모델 자체 훈련·초기 파인튜닝, 네이티브 앱, 필수 브라우저 확장.
- 군말·말 더듬음·얼굴에서 이해도·감정·정서 문제를 자동 진단하거나 치료하는 기능.
- 발표 중 자동 대본 덮어쓰기, 사용자를 대신한 발표·질문 답변.
- 범용 팩트체크·외부 웹 자동 검색. 자료와의 일치를 다루며 자료 자체의 사실성을 보증하지 않는다.
- 초기 PDF/PPTX 추출·OCR·벡터 DB·회원·결제·팀 협업·클라우드 녹화 보관.

## 8. 성공 지표와 평가

| 지표 | 측정 방법 | 해석 원칙 |
| --- | --- | --- |
| 자기 설명의 근거 충족 | 사람이 정한 핵심 명제별 답변 근거·누락·왜곡 | 말 수·군말 감소·자신감으로 대체하지 않음 |
| 동등 질문의 답변 | 같은 개념의 표현·사례를 바꾼 질문, 도움 여부 기록 | 같은 문장 암기와 구분, 한 번으로 학습 효과 확정 금지 |
| 의미 보존 | 수치·단위·조건·부정·한계·전문 용어의 훼손·근거 없는 추가 | 자동 검사와 사람 판정을 분리 |
| 준비 부담 | 자료 입력부터 이해·수정·질문·재연습까지 시간 | 질문 시간 포함, E1의 전체 10시간을 절감 가능한 시간으로 삼지 않음 |
| 전체 발표 | 필수 내용 전달·실제 시간·선택적 부담 | 부분 연습의 성공을 전체 발표로 확대하지 않음 |
| 실행 성능 | 모델·양자화·입력 길이별 지연·메모리·실패율 | 실측 전 성능 수치·동시 사용자 수 약속 금지 |

첫 비교는 같은 로컬 모델로 “쉽게 수정해 줘”만 요청하는 조건과 구조화 코칭을 비교해 흐름의 추가 가치를 분리한다. 이어서 수동 점검과 비교한다. 비슷한 난도의 자료와 질문을 사용하고 순서를 교차한다. 5명 이상 탐색 과업 검증을 계획하되 아직 참가자 모집·실험은 하지 않았다. 만족도뿐 아니라 설명 정확도와 질문 부담을 함께 보고한다.
