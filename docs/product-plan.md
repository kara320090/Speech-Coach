# Speech-Coach 서비스 기획서

기준일: 2026-10-29 · 구현 확인 기준: `086a83a`, E2E·CI 갱신 확인: `625b942` · 대상: 설치 없이 사용하는 노트북·PC 웹 서비스

## 1. 서비스 정의

Speech-Coach는 대학생이 발표에서 반복되는 어려움을 관찰하고, 당시 상황을 짧은 질문으로 확인한 뒤, 준비·화면·연습 조건을 바꾸어 실제로 도움이 되는지 시험하는 웹 서비스다. 목표 시간과 필수 내용을 기준으로 대본을 수정하는 기능도 이 과정에 연결한다. 현재 구현은 시간·속도 안내와 녹음·검토 구간·기록 비교까지다. 원인 확인 질문·조건 시험·개인 실측 기반 대본 수정·필수 내용 보존은 **개발 예정 기능**이다.

제품의 핵심 과업은 **연습 → 관찰 확인 → 당시 상황 질문 → 바꿔 볼 조건 선택 → 재연습 → 변화·부담 확인**이다. 사용자가 매번 녹음을 처음부터 재생하며 수정할 부분을 찾는 부담을 줄인다.

**강조하는 피드백 — 대본 이해·숙지 교차 확인(F15, 개발 예정):** 많은 학생이 AI 에이전트로 발표 자료와 대본을 만들지만, 대본 문장을 완벽히 숙지하지 못한 채 연습해 숙지하지 못한 부분에서 막히고, 그 때문에 긴장감이 커지거나 자신감이 떨어진다는 것이 팀의 관찰이다(비율은 조사 전). 그래서 피드백 단계에서 막힘·긴 침묵·대본과 다른 발화가 나온 구간을 짚어 “이 부분을 잘 이해하지 못한 것 같아요. 잘 이해한 게 맞나요?”라고 교차 확인한다. 응답에 따라 ① 이해했다면 사용자가 직접 설명한 표현을 반영해 대본을 말하기 자연스러운 문장으로 다듬고, ② 잘 모르겠다면 원문 근거만으로 핵심을 쉽게 정리해 보여 준 뒤 다시 설명해 보게 하며, ③ 표현이 어색했다면 구어체로 바꾼다. “이해했다”는 응답도 그대로 믿지 않고, 대본을 보지 않은 자기 말 설명과 원문에서만 만든 확인 질문으로 다시 교차검증해 실제로는 이해가 부족한 부분을 찾는다(사용자를 탓하는 표현은 쓰지 않는다). 원문·사용자 설명·수정안·재연습 발화를 나란히 놓고 교차검증해 의미가 유지됐는지, 자기 말로 전달됐는지, 막힘이 줄었는지를 비교 분석한다. 이를 통해 대본을 깊이 이해하고 완벽히 숙지하도록 돕는다. 감점 방지, 발표 성공, 준비 시간 절감 효과를 이미 달성한 것으로 홍보하지 않는다.

## 2. 사용자와 사용 장면

| 항목 | 정의 |
| --- | --- |
| 핵심 사용자 | 수업·팀 프로젝트 발표를 맡고 혼자 연습하는 대학생 |
| 사용 시점 | 발표 자료와 대본을 준비한 후, 실제 발표 전 반복 연습 |
| 주 사용 환경 | 집·빈 강의실의 노트북 또는 PC 웹브라우저, 마이크 사용 가능 환경 |
| 사용자 목표 | 정해진 시간에 필수 내용을 전달하고, 수정할 부분을 빠르게 확인 |
| 사용자가 하는 일 | 목표·대본·필수 내용 입력, 실제 연습, 관찰 확인·선택적 상황 설명, 조치 선택 |
| 서비스가 자동화하는 일 | 검토 구간·재생 위치 연결, 측정값·인식 문장 정리(현재). 추후 짧은 후속 질문, 관찰과 사용자 설명을 구분한 요약, 원문 기반 핵심어·전환 단서, 선택 조건 적용·변경 이력, 재연습 전후 비교, 필요한 경우 대본 수정·필수 내용 보존 검사 |
| 사용자에게 남기는 판단 | 관찰이 맞는지, 당시 어떤 어려움이 있었는지, 어떤 조치를 시험할지, 제안이 실제로 도움이 됐는지 |
| 플랫폼 결정 | 웹브라우저. 설치 파일·모바일 네이티브 앱·에뮬레이터는 제품에 필요하지 않음 |

웹캠 녹화는 선택 사항이다. 표정·자세·감정 평가를 제품 핵심에 추가하지 않는다. 마이크 권한이 없으면 시간 측정 흐름을 계속 제공한다.

## 3. 문제와 근거

사용자는 10분 이상 11분 미만이어야 감점되지 않는 대학교 응용 프로젝트 발표를 준비하며 10분 30초를 목표로 연습했다. 긴장하면 말이 빨라져 10분을 채우지 못했고, 자세히 설명하면 11분을 넘겼다. 시간을 확인하려고 화면·시계를 보면 설명 흐름이 끊겼고, 연습과 실제 발표의 속도가 달랐다. 직접 녹음하고 웹캠으로 녹화한 뒤 다시 보며 점검했고, 이 과정에 시간이 오래 걸렸다고 말했다. 준비에는 대사 암기와 여러 활동을 합쳐 약 10시간이 들었다고 기억한다.

이 경험에서 제품 방향이 나온다. 반복 연습과 “시간을 지키겠다”는 다짐만으로는 해결되지 않았고, 시간을 확인하는 행동 자체가 흐름을 끊었다. 그래서 문제를 지적하는 데서 끝내지 않고, 그 순간의 어려움을 확인해 표시 방식·준비물·연습 조건을 바꿔 다시 연습하도록 돕는다.

이 사례는 한 사람의 회고다. 10시간은 영상 검토 시간만이 아니며 정확한 측정값도 아니다. 10~11분 규칙과 10분 30초 목표는 학생이 종이 기록에 적고 확인한 내용이다. 실제 발표 종료 시각, 실제 감점 여부, 준비 활동별 소요 시간은 미확인이다. 여러 대학생의 공통 문제나 서비스 도입 효과로 확대하지 않는다. 상세 근거와 종이 양식에 옮길 문구는 [문제 정의 캔버스](problem-canvas.md)에 있다.

## 4. 경쟁 비교에서 정한 제품 방향

타이머, 한국어 음성 분석, 녹음, 검토 구간, 이전 기록 비교 자체를 독점 차별점으로 주장하지 않는다. Talkli와 SayNow는 비교·성장 추적을 안내하고, PT샌드백은 장표별 시간 설정과 발표 연습을 제공한다. SayNow의 공개 웹 대본 도구는 시간별 문장 틀을 제공하지만 테스트에서 길어진 내용을 자동 축약하지 않았다. [경쟁 서비스 분석서](competitive-analysis.md)에 확인 범위와 증거를 기록했다.

**선택한 구현 방향: 원인을 단정하지 않는 상황 확인과 연습 조건 설계·재점검.**

군말을 발견하면 재생으로 관찰을 확인하고, 사용자가 겪은 어려움을 최대 3개의 질문으로 구체화한다. 다음 문장이 기억나지 않을까 걱정됐다는 설명이 나오면 핵심어 메모·전환 단서를 선택해 시험한다. 질문을 건너뛰어도 연습을 계속한다. [상세 코칭 설계](coaching-design.md)에 대화·분기·조건·검증 기준을 적었다. 이 예시는 실제 경험·인과관계·효과의 증거가 아니다.

대본 수정은 내용의 길이·구조가 문제인 경우 선택하는 조치로 연결한다.

1. 사용자 대본과 필수 전달 항목에 고정 ID를 부여한다.
2. 실제 연습 시간을 측정하고, 전사 결과와 대본 구간의 대응이 충분할 때만 구간별 시간을 추정한다.
3. 시간 초과 시 중복 설명을 줄이는 수정안, 미달 시 사용자가 제공한 근거·예시를 활용하는 보완안을 제시한다.
4. 수정 전후 필수 내용, 수치, 부정 표현, 조건·단위가 달라진 부분을 근거와 함께 보여 준다.
5. 사용자가 선택한 수정 항목을 다음 연습에 연결해 해결·미해결·판단 불가로 확인한다.

이것은 팀의 제품 설계 결정이다. 세 경쟁사의 모든 요금제에 해당 기능이 없다는 조사 결론이나 우월성이 입증된 결과는 아니다. 경쟁사의 기능 유무와 별개로 사용자가 완료해야 하는 과업과 산출물을 구체적으로 정의했다.

## 5. 범위와 구현 단계

| 단계 | 포함 범위 | 현재 상태 | 다음 단계 진입 조건 |
| --- | --- | --- | --- |
| R0 기본 연습 | F1–F6: 설정, 시간·속도, 구간 계획, 녹음·선택 영상, 검토 구간, 비교 | 코드 존재, 단위 40개(`9d2a10b`)·기존 시나리오 CI 4개 통과. 번호 미배정 영상 불러오기도 이 단계에서 함께 검증 | 실제 장치·분석 품질·저장 예외, 실제 음성 인식 중계 검증 |
| R1 상황·자료 연결 | F7–F8·F13, F15 이해 확인 질문: 대본·필수 항목·시간 범위, 관찰 확인·짧은 질문, 대본 이해 교차 확인 | 계획·미구현 | 입력·버전·질문 상한·오탐·건너뛰기·이해 확인 응답 기록 검증 |
| R2 조건 시험·재점검 | F14·F11: 단서·표시·연습 조건 선택, 조건 기록, 재연습 비교 | 계획·미구현 | 적용·되돌리기·무효·악화·조건 차이 처리 |
| R3 대본 수정·결과 연결 | F9–F10·F12, F15 대본 다듬기·교차검증: 문장 수정·자연스러운 말투 다듬기·내용 보존·4열 비교·내보내기, F11 연결 | 계획·미구현 | 의미 보존·비용·실패 처리 및 전체 연습 검증 |

첫 대본 입력은 UTF-8 TXT 파일(1MB 이하) 불러오기와 직접 붙여넣기·편집이다. 2026-10-29 대본 패널 ‘대본 편집’에 TXT 불러오기를 붙이고, 불러온 파일명 기록과 같은 조건 재연습 때 그 기록의 대본 불러오기를 구현했다(F7 일부, 브라우저 안에서만 처리). 필수 항목·버전 ID·수정안은 아직 미구현이다. PDF/DOCX/PPTX 내용 추출·OCR·슬라이드 자동 조작·대본 자동 스크롤은 후속 범위로 분리한다. 파일 형식 지원을 이미 구현된 것처럼 쓰지 않는다.

## 6. 범위 밖

- 모바일·데스크톱 설치형 앱, 브라우저 확장 설치를 필수로 하는 기능.
- 표정·자세·감정 평가, 발음 장애 진단, 발표 점수·학점·감점 예측.
- 실제 발표 중 자동으로 대본을 바꾸거나 사용자 대신 발표하는 기능.
- 군말·녹음에서 긴장·불안·심리 원인을 자동 판정하는 기능, 심리 상담·의료 진단.
- 5 Whys를 모든 사용자에게 다섯 번 묻는 대화. 질문은 관찰 확인 외 항목당 기본 최대 3개다.
- 익숙한 청중 앞 연습을 위해 서비스가 다른 사람에게 자동 연락하거나 청중을 모집하는 기능.
- 모든 사실의 진위를 외부 세계와 대조하는 범용 팩트체크. 제공 자료와 수정문·실제 발화 사이의 일치 여부를 다룬다.
- 회원·팀 협업·결제·클라우드 녹화 보관. 필요성이 검증되기 전에는 추가하지 않는다.

## 7. 성공 기준

| 지표 | 측정 방법 | 사용 원칙 |
| --- | --- | --- |
| 점검 소요 시간 | 연습 종료부터 사용자가 수정할 항목·시험할 조치를 확정할 때까지. 상황 질문에 답하는 시간을 포함 | 수동 검토와 서비스 사용 조건을 비교. 전체 준비 10시간과 혼동하지 않음 |
| 시간 범위 충족 | 최종 전체 연습의 실제 초가 사용자 최소·최대 범위 안인지 | 예상 시간과 구분, 구간 재연습만으로 전체 성공을 선언하지 않음 |
| 필수 항목 전달 | 사전에 정한 항목 중 실제 발화에서 근거가 확인된 수 | AI 판단과 사람이 확인한 정답을 구분 |
| 잘못된 수정 제안 | 수치·조건·부정 의미 훼손, 근거 없는 내용 추가 건수 | 제안 수와 함께 보고하고 사용자의 거절 사유 기록 |
| 반복 점검 부담 | 같은 지적을 다시 찾은 횟수, 전체 재생 횟수 | 실제 사용 기록을 확보한 뒤만 수치 제시 |
| 조건 시험의 유용성 | 분석 가능한 구간의 군말 횟수·분당 빈도, 내용·시간·선택적 부담 | 전사 품질·변경 조건을 기록, 군말 감소만으로 성공 판정 금지 |
| 질문 부담 | 답변 시간·질문 수·건너뛰기·원치 않는 추정 | 분석 시간 절감과 함께 보고, 원인 확인을 강요하지 않음 |
| 대본 이해·전달 | 이해 확인 응답, “이해했다” 응답과 설명·확인 답의 일치율, 사용자 설명과 원문의 의미 일치, 다듬은 대본으로 재연습한 구간의 막힘·긴 침묵·대본과 다른 발화 변화, 필수 내용 보존 | 이해 여부를 자동 판정하지 않음. 문장을 외워 그대로 읽은 경우와 자기 말로 전달한 경우를 구분해 기록 |

초기 검증은 5명 이상을 모집하는 계획으로 둔다. 수동 검토와 서비스 사용 순서를 교차하고 비슷한 난도의 두 발표 과업을 사용한다. 표본이 작으면 탐색 결과로 보고한다. 성공 수치·절감률은 아직 없다.

## 8. 운영·일정·역할

달력 일정과 팀원별 담당자는 이 대화에서 확인되지 않았으므로 임의 배정하지 않는다. 과업의 순서와 완료 조건은 다음과 같다.

| 우선순위 | 과업 | 산출물·완료 조건 | 담당 역할 |
| --- | --- | --- | --- |
| P0 | R0 실제 검증·저장 오류 확인 | 실제 장치 E2E 결과, 저장·삭제 실패 안내 점검 | 프런트엔드·검증 |
| P0 | 대본/필수 항목/시간 범위 모델 | F7–F8, 버전 데이터와 입력 검사 | 프런트엔드 |
| P0 | 상황 확인·조건 시험 | F13–F14, 질문 상한·선택·적용·되돌리기·조건 기록 | 기획·프런트엔드·검증 |
| P0 | 대본 이해 교차 확인 | F15, 이해 확인 질문·응답 분기·자연스러운 대본 다듬기·4열 교차검증 | 기획·프런트엔드·AI·검증 |
| P1 | 대본 수정 확장 | F9–F10, 원문 보존·제안 근거·실패 대응 | AI·서버·검증 |
| P0 | 수정 항목별 재연습 비교 | F11, 동일 조건 판정·변경 조건 안내 | 프런트엔드·검증 |
| P1 | 내보내기·보관 안내 | F12, 손실·복원 범위 안내 | 프런트엔드 |
| P1 | 사용자 검증·경쟁 기능 재확인 | 지표 실측, 접근하지 못한 기능의 확인 기록 | 기획·검증 |

초기 F13–F14는 규칙형 질문·사용자 선택·로컬 단서 편집부터 구현할 수 있다. 대본 재작성 API가 완성되어야 조건 시험을 시작할 수 있는 구조로 묶지 않는다.

대본 수정(F9–F10)용 AI 모델·공급자·비용 한도와 공개 배포 URL은 미정이다. 번호 미배정 영상 불러오기의 글자 변환은 코드상 AI Gateway 음성 인식(기본 모델 값 `google/gemini-3.5-transcribe`)과 서버 누적 길이 한도를 쓰지만 실제 호출·배포는 미검증이다([설명](import-feature.md)). 이 연결을 대본 수정이나 코칭 질문의 AI 공급자 결정으로 보지 않는다. 호출 전 텍스트 전송 범위, 보관 정책, 요청별 예상 비용을 정하고 서버에서 사용량을 제한한다.
