# 검증 계획서·실행 결과

현재 제출 검사는 `docs/scenarios.yaml`의 S1–S7·S9 8개와 같은 이름의 E2E를 따른다. 아래 P05–P11은 전체 확장 기획의 검증 목표로, 제출 흐름과 구분한다.

## 현재 제출 실행 확인 (2026-10-30)

Node 22 단위 184개 통과. [실제 Docker CI](https://github.com/kara320090/Speech-Coach/actions/runs/40928210822)에서 모델 포함 이미지 빌드 약 60초, 모델 기동 약 6초, 외부 키 없는 실제 질문 생성·한국어 전사와 화면 흐름 8개를 모두 확인했다. 화면 검사는 2.9분이다. 합성 음성 입력을 사용했으며 사람의 음성·얼굴 정확도나 학습 효과 검증을 뜻하지 않는다.

## 2026-10-30 AI 처리 역할

새 대본 생성(F22)은 `/create-script.html`·`POST /api/scripts/generate`에서 Gemini 3.8 Flash로 처리한다. 사용자가 입력한 주제·근거 자료만 전송하며, 초안 확인 후 기존 기록을 보존한 새 버전으로 저장한다. 기존 대본의 개념 분석·쉬운 표현 수정·질문·답변 검토는 Qwen, 음성 전사는 faster-whisper로 처리한다. 자체 AI와 Gemini의 상태·실패는 독립적이며 자동 공급자 대체는 없다. API·설정은 [역할 분리 명세](gemini-coach.md)를 따른다.

**현재 구현 상태:** 자체 실행 텍스트 코칭과 음성 전사의 첫 구현이 추가됐다. 아래 전체 기획의 완료 조건과 구현된 부분은 [구현 범위](local-ai-implementation.md)에서 구분한다. 외부 AI Gateway와 브라우저 실시간 음성 인식은 제거/비활성화했다.


기준일: 2026-10-29. 기획 완료, 코드 존재, 자동 검사 통과, 실제 사용 검증은 서로 다른 상태다.

다음은 제품 시험용 예시이며 사용자의 실제 발표 사실이 아니다.

| “준비 전반에 약 10시간” | “영상 검토만 정확히 10시간” | 범위·정확성 의미 변경 |

## 4. 사용자 과업 검증

대상: 발표를 준비하는 대학생 5명 이상 모집 계획. 아직 인터뷰·실험을 수행하지 않았다.

1. 비슷한 난도의 발표 두 개와 동일한 시간·필수 항목 기준을 준비한다.
2. 수동 녹음 검토와 서비스 사용의 순서를 교차한다.
3. 연습 종료→수정 항목 확정까지의 시간, 전체 재생 횟수, 잘못된 지적, 채택·거절 사유를 기록한다.
4. 마지막 전체 연습의 실제 시간과 필수 항목 전달을 사람이 확인한다.
5. 개별 결과와 중앙값·범위, 중도 실패·미측정 사례를 함께 보고한다.

점검 시간 단축이 있어도 내용 누락이 늘면 성공으로 판단하지 않는다. 이 실험으로 전체 발표 준비 시간이나 실제 학점 개선을 증명했다고 주장하지 않는다.

#### AI 도구로 만든 대본의 숙지 문제 확인 — 추가 계획

“대다수 학생이 AI로 만든 대본을 완벽히 숙지하지 못한다”는 팀 관찰을 사실로 쓰기 전에, 발표를 준비하는 대학생을 대상으로 ① 발표 자료·대본 작성에 AI 도구를 쓰는지, ② 대본 문단의 핵심을 자기 말로 설명할 수 있는지(사람이 원문과 대조), ③ 연습 중 막힌 구간과 이해 부족 문단이 겹치는지, ④ “이해했다”는 자기 평가와 사람이 판정한 설명 일치도가 얼마나 다른지, ⑤ 대본을 숙지하지 못했을 때 긴장감·자신감 응답이 어떻게 다른지를 확인한다. 결과가 나오기 전에는 비율·대다수 표현을 확정하지 않는다.

같은 검토 정보를 받는 “관찰만 제공” 조건과 “짧은 질문·선택 조치 제공” 조건을 비교한다. 참가자별 비슷한 구간을 사용하고 순서를 교차한다. 선택 조치는 한 번에 하나로 제한하고, 여러 조건이 달라지면 따로 기록한다. 질문 시간도 전체 점검 시간에 포함한다.

관찰 정답은 사람이 녹음으로 확인하며 전사의 군말 누락·오인식을 포함한다. 횟수·분당 빈도·분석 가능한 길이, 내용 누락, 실제 시간, 선택적 부담 응답, 질문 수·건너뛰기·잘못된 원인 추정, 조치 채택·거절 이유를 기록한다. 짧게 말하거나 말을 멈춰 횟수만 줄어든 사례, 메모가 오히려 방해된 사례도 포함한다.

군말이 줄어도 내용·시간·부담이 악화되면 개선으로 확정하지 않는다. 반복 효과·순서 효과와 실제 발표 환경의 차이가 남으므로 한 번의 전후 차이를 원인 증명으로 쓰지 않는다. 실제로 단서를 사용할 수 없는 경우 단서를 줄인 전체 연습 결과를 별도로 확인한다. 아직 실행한 실험이나 검증된 감소율은 없다.

## T22 — 생성과 자체 AI의 독립성

Gemini 오류를 반환한 뒤 concepts·rewrite·question·review 4개 과업이 자체 모델에서 성공하는지 검사한다. 자체 모델 중단 시 Gemini 자동 호출이 없는지도 확인한다. 새 대본의 명시적 검토·버전 보존·되돌리기·생성 실패 시 코칭 이동은 별도 미디어 E2E에서 가짜 응답으로 검사한다. 실제 공개 연결은 Vercel→Render→운영 PC로 별도 확인하며, 가짜 응답 검사를 모델 정확도 검증이라고 부르지 않는다.
