## 3. 내용 보존 검증 예시 — 합성 자료

다음은 제품 시험용 예시이며 사용자의 실제 발표 사실이 아니다.

| 원문 근거 | 수정/발화 | 기대 |
| --- | --- | --- |
| “30명을 대상으로 조사했다” | “300명을 대상으로 조사했다” | 수치 변경 의심 |
| “효과는 아직 검증하지 않았다” | “효과를 검증했다” | 부정·검증 상태 변경 |
| “인터넷이 연결된 경우 사용할 수 있다” | “항상 사용할 수 있다” | 조건 삭제 |
| “준비 전반에 약 10시간” | “영상 검토만 정확히 10시간” | 범위·정확성 의미 변경 |
| “표본이 작아 일반화하기 어렵다” | 해당 문장 삭제, 한계는 필수 항목 | 필수 항목 누락 |
| “점검 시간을 줄이는 것이 목표다” | “검토에 드는 시간을 단축하려 한다” | 의미 유지 후보, 근거 제시 |

각 유형의 여러 사례를 분리된 검증 세트로 관리한다. 오탐·미탐·판단 불가를 모두 집계하며 AI 결과를 정답으로 삼지 않는다. 초기 출시 기준은 필수 의미 훼손 사례가 경고 없이 통과하지 않는 것, 자료 없는 사실을 추가하지 않는 것이다. 사람이 판정한 정답과 비교한 정확도는 실제 평가 후에만 기록한다.

## 4. 사용자 과업 검증

대상: 발표를 준비하는 대학생 5명 이상 모집 계획. 아직 인터뷰·실험을 수행하지 않았다.

1. 비슷한 난도의 발표 두 개와 동일한 시간·필수 항목 기준을 준비한다.
2. 수동 녹음 검토와 서비스 사용의 순서를 교차한다.
3. 연습 종료→수정 항목 확정까지의 시간, 전체 재생 횟수, 잘못된 지적, 채택·거절 사유를 기록한다.
4. 마지막 전체 연습의 실제 시간과 필수 항목 전달을 사람이 확인한다.
5. 개별 결과와 중앙값·범위, 중도 실패·미측정 사례를 함께 보고한다.

점검 시간 단축이 있어도 내용 누락이 늘면 성공으로 판단하지 않는다. 이 실험으로 전체 발표 준비 시간이나 실제 학점 개선을 증명했다고 주장하지 않는다.

같은 검토 정보를 받는 “관찰만 제공” 조건과 “짧은 질문·선택 조치 제공” 조건을 비교한다. 참가자별 비슷한 구간을 사용하고 순서를 교차한다. 선택 조치는 한 번에 하나로 제한하고, 여러 조건이 달라지면 따로 기록한다. 질문 시간도 전체 점검 시간에 포함한다.

관찰 정답은 사람이 녹음으로 확인하며 전사의 군말 누락·오인식을 포함한다. 횟수·분당 빈도·분석 가능한 길이, 내용 누락, 실제 시간, 선택적 부담 응답, 질문 수·건너뛰기·잘못된 원인 추정, 조치 채택·거절 이유를 기록한다. 짧게 말하거나 말을 멈춰 횟수만 줄어든 사례, 메모가 오히려 방해된 사례도 포함한다.

군말이 줄어도 내용·시간·부담이 악화되면 개선으로 확정하지 않는다. 반복 효과·순서 효과와 실제 발표 환경의 차이가 남으므로 한 번의 전후 차이를 원인 증명으로 쓰지 않는다. 실제로 단서를 사용할 수 없는 경우 단서를 줄인 전체 연습 결과를 별도로 확인한다. 아직 실행한 실험이나 검증된 감소율은 없다.

## 5. 운영·브라우저 검증

- 실제 마이크·선택 웹캠, 권한 거부·재시도, 음성 인식 미지원·네트워크 중단.
- 10분 연습의 기준 시계 대비 오차·일시정지·백그라운드 탭·장치 중단.
- IndexedDB 저장·용량 부족·삭제 실패·브라우저 재시작 후 기록 조회.
- 키보드·확대·라벨·상태 문구, 주요 PC 화면 크기.
- `docker compose up --build`, `/__health`와 배포 SHA, 없는 경로 404, 실제 CI 결과.
- `/api/transcribe`: 실제 AI Gateway 응답 형식(구간 정보 유무), 키 노출 없음, 배포 환경 로그에 소리 미보관, 누적 한도 재시작 동작. 현재는 가짜 게이트웨이 단위 검사만 있음.
- 대본 수정 AI API 구현 후 비밀값 노출·전송 선택·입력 크기·요청 제한·지연·취소·오래된 응답·재시도 비용.

기존 commit의 Docker·health·S1–S4 CI 성공은 확인했다. 문서 변경 commit의 CI는 push 후 별도로 확인한다. 공개 배포·실제 장치·별도 미디어 검증과 혼동하지 않는다.
