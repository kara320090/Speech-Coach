# 영상·소리 파일 불러오기와 음성 전사

F16 파일 불러오기·전사·군말 후보와 F21 영상 측정을 제공한다.

## 흐름

1. `/import.html`에서 파일과 목표 시간을 고른다. 300 MB·30분 제한이며 브라우저가 디코딩할 수 있는 파일이어야 한다.
2. 소리를 브라우저에서 16kHz 모노로 풀어 긴 침묵을 찾는다. 선택한 눈 깜빡임 분석은 번들 MediaPipe 모델·WASM을 브라우저에서 실행한다. 얼굴 프레임은 전송하지 않는다.
3. 글자 변환을 명시적으로 켠 경우에만 약 20초(±5초) WAV 조각을 같은 출처 `POST /api/transcribe`로 보낸다.
4. `AI_PROVIDER=gateway`에서는 서버가 `AI_GATEWAY_API_KEY`로 Gateway 전사를 호출한다. local 모드는 기존 자체 전사 설정을 사용한다. 키·모델이 미설정이면 전사 불가를 알리고 로컬 분석을 유지한다.
5. 전사 글로 평균 속도·반복·군말 후보를 계산한다. 시간 정보가 없으면 조각 전체 범위를 사용하고 `timingPrecision: chunk`를 유지한다. 정확한 단어·군말 발생 시각으로 표현하지 않는다.
6. 파일·분석은 브라우저 IndexedDB에 저장한다. 군말·침묵·깜빡임으로 감정이나 이해 부족을 단정하지 않는다.
7. 스튜디오의 '녹화된 영상 불러오기'로 들어왔다면 대본·근거를 함께 입력해 분석 후 스튜디오 결과로 돌아온다. 대본 위치를 사용자가 확인한 뒤 기존 대화·문단 수정 흐름으로 이어진다. 가져오기만으로 코칭·수정 요청을 보내지 않는다.

글자 변환을 끄면 소리도 브라우저 밖으로 보내지 않는다. 켜면 소리만 서버에 설정된 전사 제공자로 전송되므로 브라우저에서만 처리한다고 안내하지 않는다. 원본 영상은 항상 브라우저에 남는다.

## 실행·한도

Gateway 설정·누적 전사 한도는 [AI Gateway](ai-gateway.md), 자체 모델 설정은 [자체 AI 실행](../local-ai/README.md)을 따른다. 기본 전사 한도는 모듈 1,800초이며 Docker Compose는 3,600초를 설정한다. 메모리 기준이라 재시작 시 초기화되고 팀 $10 한도를 보장하지 않는다.

16kHz 모노 PCM16 WAV만 받고 크기·동시 요청·누적 길이를 제한한다. 재시도나 유료 모델 자동 대체는 없다. 실패·취소 시 로컬 침묵 분석과 원본을 유지한다. 서버는 소리·전사·키를 본문 로그에 남기지 않는다.

## 검증 범위

S6는 첫 화면 메뉴에서 진입해 실제 제공된 약18초 MP4를 고르고 소리 전송에 동의한 뒤 실제 Gateway 전사와 브라우저 MediaPipe 분석을 함께 실행한다. HTTP 200·비어 있지 않은 전사 글·평균 속도·영상 재생·깜빡임 횟수를 확인한다. 별도 브라우저 검사는 가져온 대본·근거·결과가 스튜디오로 이어지는지 확인한다. 가짜 전사 응답 검사는 응답 처리 회귀 검사용이며 실제 인식 정확도 검증이 아니다.

사용자 동의 후 실제 영상의 음성만 Gateway에 1회 보내 HTTP200·전사 글·조각 단위 구간을 확인했다. 단어별 시각이나 전사·깜빡임 정확도를 정답 데이터로 검증한 것은 아니다. 짧은 영상만으로 장기 추세도 검증할 수 없다.
