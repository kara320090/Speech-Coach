## 3. 확장 시나리오 — 개발 예정

### S5: 목표 시간과 필수 내용을 준비한다

1. “발표 자료 준비”에서 대본을 붙여넣거나 TXT 파일로 불러온다.
2. 최소 4분 30초·최대 5분을 입력한다. 이 값은 테스트 예시이며 사용자 과제 조건이 아니다.
3. 필수 전달 항목과 근거 문장을 입력한다.
4. “원본 저장”을 누른다.

기대 결과: 원본 버전·조건·필수 항목이 연결되어 저장된다. 잘못된 범위에서는 저장되지 않고 이유가 표시된다. 관련: F7–F8 / AC-07–08 / UI-05.

### S6: 초과한 발표 대본을 수정한다

1. 저장한 대본으로 전체 연습을 마친다.
2. “수정안 검토”를 연다.
3. 중복 설명 축약안의 원문·제안·근거·필수 내용 검사를 읽는다.
4. 채택할 항목의 “적용”을 누른다.

기대 결과: 원본은 보존되고 새 버전이 생성된다. 보호할 수치·조건을 바꾼 제안은 변경 의심으로 표시되고 조용히 자동 적용되지 않는다. 관련: F9–F10 / AC-09–10 / UI-06.

### S7: 시간이 부족한 발표를 근거에 따라 보완한다

1. 미달 결과에서 “수정안 검토”를 연다.
2. 사용자가 실제로 제공한 예시·근거가 있는 구간의 보완안을 확인한다.
3. 자료가 부족한 항목의 추가 근거를 입력하거나 보완을 보류한다.
4. 확인한 제안을 새 버전으로 저장한다.

기대 결과: 임의의 성과·통계·경험을 추가하지 않는다. 미달을 해결하기 위해 무의미한 문장을 채우지 않으며 내용이 부족하면 그 상태를 남긴다. 관련: F9–F10 / AC-09–10 / UI-06.

### S8: 고친 구간과 전체 발표를 다시 확인한다

1. “수정 항목 재점검”에서 항목을 선택한다.
2. “이 구간 연습”으로 재연습한다.
3. 이전과 이번의 발화 근거·실제 시간·필수 내용 상태를 확인한다.
4. “전체 발표 확인”으로 전체 연습을 수행한다.
5. 결과를 내보낸다.

기대 결과: 부분 결과와 전체 실측이 구분된다. 같은 기준의 항목은 해결/미해결/판단 불가로 표시되고, 조건 변경은 별도 안내된다. 관련: F11–F12 / AC-11–12 / UI-07–08.

### S9: 관찰을 확인하고 당시 상황을 설명한다

1. 결과의 반복 후보를 재생하고 관찰을 확인하거나 교정한다.
2. “상황 확인”에서 당시 어려움을 설명한다. 긴장했다는 답변이 있으면 걱정된 조건을 후속 질문으로 확인한다.
3. 서비스가 요약한 본인 설명을 확인한다. 모르겠음·건너뛰기도 선택 가능하다.

기대 결과: 관찰·본인 설명·추정을 구분한다. 질문은 기본 최대 3개이며 긴장이 기본 원인으로 선택되지 않는다. 오탐·문제 아님이면 해당 지적을 닫을 수 있고 연습은 계속된다. 관련: F13 / AC-13 / UI-09.

### S10: 반복이 생기는 조건을 바꾸어 시험한다

1. “연습 조건 시험”에서 원문 기반 핵심어 메모 등 제안을 확인한다. 이 예시는 검증된 효과가 아니다.
2. 한 가지 조치를 선택하고 적용 미리보기를 확인한다.
3. 기준과 가능한 한 같은 구간을 다시 연습한다.
4. 군말 횟수·분당 빈도, 내용·시간·선택적 부담과 바뀐 조건을 함께 확인한다.
5. 도움이 없으면 되돌리거나 다른 방법을 선택한다. 단서 사용이 불가능한 실제 발표에 대비하는 전체 연습도 별도로 수행한다.

기대 결과: 원인을 몰라도 조치를 선택할 수 있다. 횟수 감소만으로 성공이나 긴장 극복을 선언하지 않는다. 연습 자체·변경 조건·전사 품질의 영향을 구분해 표시한다. 관련: F14·F11 / AC-14·11 / UI-10·07.

### S11: AI로 만든 대본의 이해·숙지를 확인하고 자연스럽게 다듬는다

1. “발표 자료 준비”에서 대본을 붙여넣고 “AI 도구로 만든 대본”을 선택 표시한다. 이 선택은 사용자 표시이며 서비스가 추정하지 않는다.
2. 전체 연습을 마친 뒤 결과에서 “확인이 필요한 구간”을 연다.
3. “이 부분을 잘 이해하지 못한 것 같아요. 잘 이해한 게 맞나요?”에 “잘 이해했어요”를 누르고 핵심을 직접 한두 문장으로 설명한다.
4. 원문 기반 확인 질문 1–2개에 답한다. 설명·답이 원문과 다른 부분이 있으면 그 부분이 표시된다.
5. 사용자 설명을 반영한 다듬기 제안과 F10 보존 검사 결과를 확인하고 “적용”을 누른다.
6. “이 구간 다시 연습”으로 재연습하고 4열 교차검증 결과를 확인한다.

기대 결과: 원문은 보존되고 새 대본 버전이 생긴다. 원문·사용자 설명·수정안·재연습 발화가 나란히 표시되고, 의미 차이·필수 내용 변경 의심은 확인 필요로 남는다. 응답 없이 이해 부족으로 기록되지 않는다. “이해했다”는 응답도 설명·확인 질문으로 교차검증되며, 다른 부분은 거짓 응답이 아니라 “설명과 원문이 다른 부분”으로 표시된다. “잘 모르겠어요”를 고르면 원문 근거의 핵심 정리 후 다시 설명하는 흐름으로 이어진다. 관련: F15·F10·F11 / AC-15 / UI-11.

## 4. 공통 문구 규칙

- 현재 측정: “실제 연습 시간”. 계산: “예상 시간 — 계산 근거 …”. 인식 실패: “측정하지 못함 — 이유 …”.
- AI 제안: “수정 제안”. 자동 적용 전 사용자 선택. 결과가 불확실하면 “확인 필요”.
- 개인정보: 로컬 저장·자체 전사·자체 LLM 텍스트 전송을 각각 설명한다. 외부 브라우저 음성 인식은 비활성화했다. 상황 질문 답변 원문은 기본 로컬 보관이다.
- 긴 침묵·반복: “다시 확인할 구간”. 무조건 나쁜 발표로 판단하지 않는다.
- 원인 질문: “긴장해서 그렇죠?” 대신 당시 어려움을 먼저 묻는다. “사용자가 설명한 상황”과 “이번 조건에서의 변화”로 표시하고 원인 확정·극복 완료로 쓰지 않는다.
- 개선 판정: 시간만 짧아졌다는 이유로 성공이라고 쓰지 않는다. 필수 내용·동일 조건·전체 실측을 함께 본다.

## 5. 웹 화면 검증 기준

주 사용 화면은 PC·노트북이며 최소 검증 크기는 1366×768로 계획한다. 확대·키보드·작은 창에서도 입력과 핵심 버튼에 접근할 수 있어야 한다. 휴대전화 접속은 레이아웃 보조 대응이며 모바일 앱 개발 범위를 뜻하지 않는다. 실제 지원 브라우저와 화면 시험 결과는 검증 후 기록한다.

## 추가 구현 화면 F21·F16

- UI-IMPORT: 기존 파일·시간·글자 변환 선택과 버튼 이름을 유지한다. ‘영상 눈 깜빡임도 이 기기에서 분석 (선택)’을 추가한다. 글자 변환과 독립이며 기본 꺼짐이다.
- UI-03: ‘군말 후보 측정’에 총 횟수·종류별 횟수·사전 기준을 표시한다. ‘눈 깜빡임 측정’에 분석/다시 분석·취소·진행률·관측 비율·구간 표·계산 근거를 표시한다. 영상 없으면 분석 버튼을 비활성화하고 이유를 표시한다.
- 기존 검토 목록에 `filler`·`blink` 항목을 같은 형식으로 연결한다. 위치·측정값·근거를 보여 주고 기존 플레이어로 이동한다.
- 실패: 모델 미로딩·지원 안 됨·인식 부족이면 ‘측정 못 함’과 이유. 취소 후 기존 결과 사용 가능. 기존 S1–S4의 버튼명과 YAML은 변경하지 않는다.


## 현재 추가 화면 UI-COACH — `/coach.html`

한 페이지에서 ① 대본·근거 입력/저장 ② 개념 선택·쉬운 대본 제안 ③ 자기 설명/질문 응답 ④ 최근 두 답변 비교·내보내기를 제공한다. 별도 계획 화면 UI-05–10을 모두 구현한 것은 아니다.

- 모델 없음: AI 버튼 비활성화, 자료 저장·편집·기본 연습 유지. 처리 위치를 안내한다.
- 수정 제안: 원문/직접 수정 가능한 제안, 수치·단위 변화 시 적용 차단, 의미 확인 후 새 버전 저장. 처음 자료로 복귀 가능.
- 질문: 풀이/근거 기본 숨김, 모르겠음·근거 보기·건너뛰기, 같은 질문 검토 3회 상한. 별도 새 질문은 사용자 선택으로 시작한다.
- 검토: 자료와 부합/보완/판단 불가, 근거·다음 행동, 사용자 맞음/동의하지 않음. 모델 결과를 이해도 점수로 표시하지 않는다.
- 비교: 질문·자료·대본이 다르면 직접 개선 비교 제한, 도움 사용 여부·원문 답변을 표시한다. 모든 기록은 JSON 내보내기에 포함된다.
- 실패: 취소·입력 변경은 오래된 응답 차단, 저장 실패는 화면 임시 보관 안내, 삭제 실패는 기록 유지·재시도 안내.

현재 추가 흐름 NC1 자료→개념→자기 설명, NC2 쉬운 대본→보존 확인→새 버전/복귀, NC3 질문→답변→재설명→비교는 `e2e/media/coaching.spec.ts`에서 검사한다. 주최 측 `docs/scenarios.yaml`·S1–S4는 변경하지 않는다. 외부 브라우저 음성 인식 선택은 비활성화했으며 파일 불러오기로 자체 전사한다.
