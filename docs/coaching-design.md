# 원인 확인과 연습 조건 설계

기준일: 2026-10-29. 사용자 제안을 구체화한 **계획·미구현** 명세다. 아래 대화와 수치는 설명용 가상 사례이며 사용자의 실제 증상·원인·검증 결과가 아니다.

## 1. 제품이 도울 일

반복 표현을 발견한 뒤 횟수만 줄이도록 요구하는 데서 끝내지 않는다. 사용자가 해당 순간을 확인하고, 반복이 생긴 조건을 설명하고, 그 조건을 바꾸는 작은 실험을 선택하도록 돕는다. 서비스의 자동화 대상은 근거 구간 연결, 짧은 질문, 선택 가능한 준비물 생성, 조건 기록, 재연습 비교다. 마음속 원인이나 감정을 자동 판정하지 않는다.

여기서 “음, 어”는 의성어보다는 군말·채움말에 해당한다. 다만 인용·강조·자연스러운 쉼을 모두 오류로 세지 않는다. 전사에서 해당 소리가 누락되거나 다른 말로 인식될 수 있어 재생 확인·교정이 필요하다. 기존 F5의 반복 표현 탐지와 정밀 군말 판별은 같은 기능이 아니며, 후자는 아직 검증하지 않았다.

**목표:** 발화를 억지로 억제하는 데 드는 부담을 줄이고, 말할 내용을 이어가기 쉬운 준비·화면·연습 조건을 마련한다. 군말 0회, 긴장 해소, 원인 규명을 보장하지 않는다.

## 2. 한 항목을 다루는 흐름

1. **관찰 확인:** 반복 후보가 있는 짧은 구간과 인식 문장을 재생한다. 문구 예: “이 구간에서 ‘음’이 반복된 것으로 표시됐어요. 직접 들어 보고 맞는지 확인해 주세요.” 사용자는 “맞음 / 잘못 인식함 / 자연스러운 표현이거나 문제로 느끼지 않음”을 선택할 수 있다. 전사가 군말을 빠뜨린 경우 사용자가 재생 위치에 직접 표시할 수 있다. 잘못 인식함·문제로 느끼지 않음이면 해당 항목의 질문은 열지 않는다.
2. **상황 질문:** “이 순간 어떤 점이 어려웠나요?”라는 열린 질문으로 시작한다. 처음부터 “긴장해서 그런가요?”처럼 원인을 유도하지 않는다. 필요하면 다음 내용이 떠오르지 않음·구간 전환·시간 확인·긴장·평소 말버릇·다른 이유·모르겠음 등을 보조 선택지로 보여 준다. 긴장을 기본 선택이나 첫 선택지로 두지 않는다.
3. **조건 구체화:** 사용자가 긴장을 언급했을 때만 “그때 어떤 점이 걱정됐나요?”라고 묻는다. 답변에 따라 다음 문장 기억, 낯선 청중, 시간 압박 등 사용자가 설명한 조건을 정리한다. 반복해서 “왜?”만 묻지 않는다.
4. **바꿔 볼 조건 선택:** 사용자 설명과 연결한 구체적인 조치 1–2개와 그 이유를 제시한다. 한 번에 하나를 선택하고, 자동으로 바뀌는 화면·대본은 미리 확인하고 적용한다.
5. **재연습:** 가능한 한 같은 구간·대본·시간 기준으로 다시 연습한다. 바꾼 조건과 그대로 둔 조건을 남긴다.
6. **확인·수정:** 반복 빈도, 내용 전달, 실제 시간, 사용자의 부담을 함께 살핀다. 도움이 없거나 불편하면 되돌리거나 다른 조건을 선택한다. 한 번 좋아졌다는 이유로 원인이 증명됐다고 결론 내리지 않는다.

질문은 관찰 확인을 제외하고 항목당 기본 최대 3개다. 사용자는 언제든 건너뛰거나 멈출 수 있다. 답을 모르거나 원인 설명을 거절해도 일반적인 연습 옵션을 선택할 수 있다. 원인 답변을 받아야 기존 연습을 계속할 수 있는 구조로 만들지 않는다. 기존 캔버스의 5 Whys는 기획 분석 양식이며 모든 사용자에게 다섯 번 묻는 대화 규칙이 아니다.

### 질문 분기 요약

| 관찰 확인 결과 | 다음 단계 | 질문 수(관찰 확인 제외) |
| --- | --- | --- |
| 잘못 인식함 | 표시 교정·제외, 일반 결과로 복귀 | 0 |
| 자연스러운 표현·문제로 느끼지 않음 | 항목 닫기, 일반 연습 계속 | 0 |
| 맞음 → 구체적 상황 답변 | 조치 제안 | 1 |
| 맞음 → “긴장했어요” | “그때 어떤 점이 걱정됐나요?” 1회 → 조치 제안 | 2 |
| 맞음 → 걱정 답변이 여전히 모호 | 보조 선택지 1회 제시 → 조치 제안 또는 일반 옵션 | 3(상한) |
| 모르겠음·건너뛰기·중단 | 일반 연습 옵션 선택 또는 그대로 연습, 원인 미확인 유지 | 그 시점까지 |

같은 내용을 표현만 바꿔 다시 묻지 않는다. 상한에 도달하면 더 묻지 않고 일반 옵션으로 넘어간다.

## 3. 가상 대화 예시

> 서비스: “이 구간에서 ‘음’이 반복된 것으로 표시됐어요. 직접 들어 보고 맞는지 확인해 주세요.”
>
> 사용자: “맞아요. 그때 긴장했어요.”
>
> 서비스: “그때 어떤 점이 걱정됐나요?”
>
> 사용자: “다음 문장을 잊어버릴까 봐요.”
>
> 서비스: “다음 내용을 떠올릴 단서가 있으면 어떤지 시험해 볼까요? 원문에서 핵심어 세 개를 뽑은 메모와 다음 구간의 첫 문장을 준비할 수 있어요.”
>
> 사용자: “핵심어 메모로 해볼게요.”
>
> 서비스: “선택한 메모를 보며 같은 구간을 다시 연습해 보세요. 끝나면 반복 표현과 내용 전달, 말하기 부담이 어떻게 달라졌는지 함께 볼게요.”

결과 화면은 “원인 해결” 대신 “이번 조건에서의 변화”를 보여 준다. 예를 들어 반복 빈도가 낮아져도 필수 설명이 빠졌거나 시선 이동이 불편했다고 답하면 성공으로 처리하지 않는다.

## 4. 사용자 설명과 조건 변경 예시

아래는 효과가 입증된 처방이 아니라 사용자 선택으로 시험할 제품 옵션이다.

| 사용자가 설명한 상황 | 제안할 수 있는 준비·환경 변경 | 재연습에서 확인할 것 |
| --- | --- | --- |
| 다음 문장을 잊을까 걱정됨 | 원문 기반 핵심어 카드·전환 문장 준비, 짧은 구간부터 연습 | 내용 누락·군말 빈도·메모 의존·사용자가 느낀 부담 |
| 다음 슬라이드에서 무엇을 말할지 헷갈림 | 구간별 첫 문장과 연결어 표시, 전환 구간만 먼저 연습 | 전환 지연·반복·핵심 내용 전달 |
| 시간 숫자를 계속 확인하느라 흐름이 끊김 | 촘촘한 숫자 대신 구간 진행 표시를 선택하고 임박 안내는 유지 | 실제 초과·미달·주의 분산에 대한 사용자 설명 |
| 대본 문장이 길어 중간에 길을 잃음 | 문장 나누기·생각 단위 표시. F9–F10으로 원문·필수 의미 보존 | 내용 보존·시간 범위·말을 이어가기 쉬웠는지 |
| 낯선 청중이 신경 쓰임 | 사용자가 선택한 익숙한 상대 앞 연습 또는 실제 장소 사전 연습 계획 | 자기 보고·준비 수행 여부·실제 상황과의 조건 차이 |
| 이유를 모르거나 답하기 원하지 않음 | 짧은 구간 연습·핵심어 메모 등 하나를 선택하거나 그대로 계속 | 원인 미확인 유지·추가 부담·관찰 가능한 변화 |

타인 앞 연습은 서비스가 누군가에게 자동 연락하거나 청중을 모집하는 기능이 아니다. 화면의 단서를 실제 발표에서 사용할 수 있는지도 확인한다. 사용할 수 없다면 단서를 줄인 전체 연습을 따로 진행한다. 도움을 받는 연습에서만 좋아진 결과를 실제 발표의 개선으로 일반화하지 않는다.

## 5. 자동화할 일과 사용자에게 남길 판단

| 서비스가 자동화할 일 | 사용자가 판단할 일 |
| --- | --- |
| 검토할 구간과 재생 위치 연결 | 관찰이 실제로 맞는지 |
| 측정값과 인식 문장 정리 | 당시 어떤 어려움을 느꼈는지 |
| 답변에 따른 짧은 후속 질문(상한 안) | 어떤 조치를 시험할지 |
| 사용자 설명과 관찰을 구분한 요약 | 제안이 실제로 도움이 됐는지 |
| 원문에 근거한 핵심어·전환 단서 생성 | 실제 발표에서 단서를 쓸 수 있는지 |
| 선택한 연습 조건 적용과 변경 이력 기록 | 조치를 유지·되돌리기·바꿀지 |
| 재연습 전후 비교, 필요한 경우 대본 수정과 필수 내용 보존 검사 | 수정 제안의 적용·거절 |

화면 문구는 “사용자가 설명한 상황”, “이번 조건에서의 변화”처럼 쓴다. “AI가 원인을 찾았어요”, “긴장 극복 완료”, “발생 원인 규명” 같은 표현은 쓰지 않는다. 사용자 답변과 한 번의 전후 비교만으로 인과관계가 증명됐다고 판단하지 않는다.

## 6. 효과 확인 기준

군말 횟수만 줄었다고 성공으로 판단하지 않는다. 결과 화면과 기록은 다음을 함께 보여 준다.

- 군말 횟수와 분석 가능한 구간 길이(초), 분당 빈도
- 필수 내용 누락 여부
- 실제 발표 시간과 목표 범위
- 긴 침묵·발화량(음절 수) 감소 여부
- 사용자가 선택적으로 응답한 부담과 편의(미응답은 미응답으로 둠)
- 바뀐 조건과 유지한 조건
- 전사 품질 상태(사용자 교정 여부 포함)와 분석 방식·버전
- 부분 연습인지 전체 연습인지

말을 덜 하거나 내용을 빼서 군말이 줄어든 경우는 개선으로 처리하지 않는다. 결과는 `improved / noClearChange / worse / uncertain` 중 하나로 남기며, 효과 없음·악화·판단 불가도 정상 결과다. 그 경우 조치를 되돌리거나 다른 조치를 선택할 수 있다. 질문에 답한 시간도 점검 소요 시간에 포함한다.

## 7. 판단·데이터 원칙

- `observation`(측정·사용자 교정), `userReport`(본인 설명), `hypothesis`(확인할 해석), `trialOutcome`(조건을 바꾼 뒤 관찰)을 분리한다.
- 사용자 설명은 존중해 기록하되 인과관계가 입증됐다는 뜻으로 저장하지 않는다. 질문과 답변이 없는데 “불안해서 군말을 한다”고 자동 기록하지 않는다.
- 군말은 횟수와 해당 녹음 길이를 함께 제시한다. 빈도는 분석 가능한 구간의 분당 횟수로 비교하며, 전사 품질·분석 버전·구간이 달라지면 제한을 표시한다. 긴 침묵이나 내용 삭제로 빈도가 낮아진 경우를 개선으로 처리하지 않는다.
- 전체 시간·필수 내용·부담을 함께 보고, 질문 시간이 기존 검토 부담보다 커지는지도 측정한다. 부담 응답은 선택 사항이며 점수 미입력을 0으로 바꾸지 않는다.
- 사용자가 말한 걱정의 원문은 기본적으로 기기에만 둔다. 외부 AI에 필요하면 전송할 최소 요약을 먼저 보여 주고 선택받는다. 심리 상태 추정·의료 진단·임상 효과 주장은 범위 밖이다.
- 여러 조건을 동시에 바꾸면 각각의 효과는 분리할 수 없다고 표시한다. 반복 연습 자체의 효과와 단순 순서 효과도 남아 있으므로 한 회차만으로 인과를 확정하지 않는다.

## 8. 구현 연결

F13 / FR-13 / AC-13은 관찰 확인과 짧은 질문, F14 / FR-14 / AC-14는 연습 조건 선택·적용·되돌리기·시험 기록을 담당한다. F11은 조건을 바꾼 재연습을 비교하고 F12는 사용자가 선택한 정보만 내보낸다. UI-09–10, S9–S10, T13–T14에 연결한다. 현재 F1–F6 코드는 이 기능을 아직 제공하지 않는다. 번호 미배정인 영상 불러오기 기능도 침묵·반복 후보와 선택 전사까지만 만들며 관찰 확인·질문·조건 시험은 없다. 향후 F13의 입력 자료로 쓸 수 있지만, 외부 음성 인식이 군말을 정리해 적을 수 있으므로 같은 재생 확인·교정 규칙을 적용한다.
