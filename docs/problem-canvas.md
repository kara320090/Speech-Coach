## 앞면

### 한 문장 문제 정의

발표를 준비하는 대학생은 혼자 연습할 때 내용을 전달하면서 시간과 말하기 속도를 함께 관리하기 어렵고, 연습 후에는 녹음·영상을 처음부터 다시 보며 고칠 구간을 직접 찾아야 한다. 특히 AI 도구로 발표 자료와 대본을 빠르게 만든 경우 대본 문장을 완벽히 숙지하지 못한 채 연습하게 되어 막히는 구간이 생기고, 고칠 구간을 찾아도 그 순간 무엇이 어려웠는지(대본 숙지인지, 기억인지, 시간 확인인지) 알기 어려워, 오래 준비하고도 실제 발표에서 시간 초과·미달을 겪는다.

### ① 상황

수업이나 팀 프로젝트 발표를 앞두고 집이나 빈 강의실에서 혼자 연습할 때 발생한다. 정해진 시간에 맞춰 내용을 전달해야 하지만, 긴장하면 말이 빨라지거나 불필요한 표현을 반복하고, 시간을 확인하려고 화면이나 시계를 보면 설명하던 흐름이 끊긴다. 그 결과 제한 시간을 초과하거나 지정된 시간을 채우지 못한다. 연습한 내용을 직접 녹음하고 웹캠으로 녹화한 뒤 다시 재생해 보며 점검해야 해서 번거롭고 시간이 오래 걸린다. 최근에는 AI 에이전트로 발표 자료와 대본을 만드는 경우가 많은데, 자료는 빨리 완성되지만 대본 문장을 완벽히 숙지하지 못한 채 연습하게 되고, 숙지하지 못한 부분에서 대본이 떠오르지 않아 말이 막힌다(팀 관찰, 비율은 조사 전).

### ② 고객

수업이나 팀 프로젝트에서 발표를 맡은 대학생이다. 발표 경험이 충분하지 않고, 짧은 준비 시간 안에 다른 사람의 도움 없이 정해진 시간에 맞춰 혼자 발표를 점검하고 개선해야 하는 사람을 핵심 대상으로 한다. AI 도구로 발표 자료·대본을 만든 뒤 그 대본을 깊이 이해하고 완벽히 숙지해 자기 말로 전달해야 하는 학생을 포함한다.

### ③ 근본 문제

발표 중에는 내용 전달에 집중하기 때문에 말하기 속도와 시간을 동시에 점검하기 어렵고, 시간을 확인하는 행동 자체가 설명의 흐름을 끊는다. 대본을 AI 도구로 만든 경우에는 대본 문장을 완벽히 숙지하지 못한 채 연습하게 되어, 숙지하지 못한 구간에서 막히기 쉽다. 연습 후에도 녹음·시간 기록·고칠 내용이 따로 남아 문제 구간을 직접 찾아야 하며, 그 순간의 어려움(대본 숙지·기억·시간 확인 등)에 맞춰 대본 표현이나 준비 방식·연습 조건을 바꾸고 다시 확인하는 방법이 없어 같은 어려움이 반복된다.

### ④ 영향

**그때 한 말·기분:** 대본을 숙지하지 못해 발표를 앞두고 긴장감이 커지거나 자신감이 떨어진다(학생 진술, 2026-10-29). “되게 시간이 오래 걸렸어.” 직접 녹음·녹화하고 다시 확인하는 과정에서 시간 부담을 느꼈다. 실제 발표를 앞두고는 준비한 내용을 너무 일찍 끝내는 건 아닌지 신경이 쓰였다.

**시간·기회:** 본인은 대사 암기와 직접 녹음·웹캠 녹화 및 반복 점검 등을 포함한 발표 준비 전반에 약 10시간이 들었다고 기억한다. 정확히 측정한 시간이 아니며 영상 검토에만 든 시간이나 전부 자동화로 줄일 수 있는 시간을 뜻하지 않는다. 10분 이상 11분 미만이어야 감점되지 않는 발표에서, 그렇게 준비하고도 제한 시간을 초과한 적과 10분을 채우지 못한 적이 모두 있었다. 실제 종료 시각과 감점 여부는 기록되어 있지 않다.

## 뒷면

### 1. 관찰 정황

**P1 — 대상:** 10분 이상 11분 미만으로 발표를 마쳐야 하는 수업·팀 프로젝트의 대학생 본인이다. 발표할 때 긴장하며, 혼자 연습하면서 발표 내용·말하기 속도·제한 시간을 함께 관리해야 했다.

**P1 — 출처:** 종이 문제정의 기록과 본인 경험(E1). 다른 대학생 인터뷰는 아직 수행하지 않았다.

**E1 — 언제:** 대학교 응용 프로젝트 발표를 준비할 때. 10분보다 짧거나 11분 이상이면 감점이어서, 내용을 잘 전달하면서 정해진 시간 안에 끝내야 했다.

**E1 — 무슨 일:**

긴장하니 말이 빨라졌다. 발표 내용에 집중하다 보니 시간이 얼마나 지났고 얼마나 남았는지 확인하기 어려웠다.

연습할 때와 실제 발표할 때의 말하는 속도가 달랐다. 시간을 확인하려고 화면이나 시계를 보면 설명하던 흐름이 끊겼고, 남은 시간을 알아도 어느 부분에서 속도를 조절해야 할지 바로 판단하기 어려웠다.

실제 발표에서 제한 시간을 초과한 적도 있었고, 지정된 시간보다 짧게 끝낸 적도 있었다. 긴장해서 말이 빨라지면 10분을 채우지 못했고, 내용을 자세히 설명하다 보면 11분을 넘기기도 했다. 연습할 때 시간을 맞춰도 실제 발표에서는 말하는 속도와 설명하는 분량이 달라져서, 정해진 시간에 맞춰 마무리하기 어려웠다.

연습할 때는 직접 녹음하고 웹캠으로 녹화한 뒤 다시 재생해 보며 점검했는데, 이 과정이 번거롭고 시간이 오래 걸렸다. 대사 암기 등 발표 준비를 포함해 대략 10시간이 들었다고 기억한다.

**E1 — 어떻게 버텼나:** 대사를 외우고 휴대폰 스톱워치를 켜고 발표 대본을 읽으면서 시간을 쟀다. 10분 30초 정도를 목표로 잡고, 시간이 길면 설명을 줄이고 짧으면 필요한 내용을 보충하는 방식으로 연습했다. 또 직접 일일이 녹음하고 웹캠으로 녹화한 뒤, 다시 재생해 보며 점검했다.

**E1 — 기분:** 준비한 내용을 너무 일찍 끝내는 건 아닌지 신경이 쓰였다. 녹음·녹화 후 직접 확인하는 과정에서 시간 부담을 느꼈다.

**E1 — 한 말:** “되게 시간이 오래 걸렸어”

**출처:** 본인의 발표 준비·발표 경험. 종이 문제정의 기록을 옮기고 학생 확인 후 기록했다(27eebf1). 준비 시간 약 10시간은 대략적인 기억이며, 실제 발표 종료 시각과 감점 여부는 확인되지 않았다.

**P2·E2:** 추가 사례 없음. 비워 둔다.

### 2. 5 Whys

**증상:** 연습을 반복해도 실제 발표에서 막힘과 시간 초과·미달이 되풀이되고, 연습 점검에 오래 걸리는 이유는 무엇인가?

1. 긴장하면 말이 빨라지고, 내용 전달에 집중하느라 경과 시간과 남은 시간을 확인하지 못한다.
2. 시간을 확인하려고 화면이나 시계를 보면 설명 흐름이 끊기고, 남은 시간을 알아도 어느 부분에서 조절할지 바로 판단하기 어렵다.
3. 연습 후에는 녹음·영상을 처음부터 다시 보며 문제 구간을 직접 찾아야 해서 점검에 시간이 오래 걸린다.
4. 문제 구간을 찾아도 그 순간 무엇이 어려웠는지(대본을 완벽히 숙지하지 못했는지, 내용을 깊이 이해하지 못했는지, 시간 확인에 신경 썼는지)는 녹음과 측정값만으로 알 수 없어, 무엇을 바꿀지 스스로 정해야 한다. (?)
5. “이해했다”는 스스로의 판단을 실제 설명으로 확인하고 대본 표현이나 연습 조건을 바꾼 뒤, 그것이 실제로 도움이 됐는지 원문·수정안·재연습 발화를 같은 기준으로 비교하는 과정이 없어 “다음엔 잘 외워야지” 같은 다짐에 기대게 된다. (?)

**근본 문제 — 앞면 ③에 반영:** 발표 중에는 내용 전달에 집중하기 때문에 말하기 속도와 시간을 동시에 점검하기 어렵고, 시간을 확인하는 행동 자체가 설명의 흐름을 끊는다. 대본을 AI 도구로 만든 경우에는 대본 문장을 완벽히 숙지하지 못한 채 연습하게 되어, 숙지하지 못한 구간에서 막히기 쉽다. 연습 후에도 녹음·시간 기록·고칠 내용이 따로 남아 문제 구간을 직접 찾아야 하며, 그 순간의 어려움(대본 숙지·기억·시간 확인 등)에 맞춰 대본 표현이나 준비 방식·연습 조건을 바꾸고 다시 확인하는 방법이 없어 같은 어려움이 반복된다.

`(?)`는 추가 확인이 필요한 원인이다. 제품 설계에 필요하다고 해서 확인된 원인으로 바꾸지 않는다. 5 Whys는 기획 분석 양식이며, 서비스가 사용자에게 다섯 번 묻는 대화 규칙이 아니다(질문은 관찰 확인 외 항목당 기본 최대 3개).

### 4. 통찰 / INSIGHT

**① 관찰 — claim:** 시간 초과·미달은 “시간을 지키겠다”는 다짐과 반복 연습만으로 해결되지 않았다. 시간을 확인하는 행동이 오히려 흐름을 끊었고, 연습 후에는 문제 구간을 직접 찾는 데 오래 걸렸으며, 무엇을 바꿔 다시 연습할지는 스스로 정해야 했다. 또 AI 도구로 대본을 쉽게 만들 수 있게 되면서, 대본을 갖고 있는 것과 그 대본을 깊이 이해하고 완벽히 숙지한 것은 별개의 문제가 됐다(팀 관찰).

**② 근거 — evidence:** 본인 경험 E1: 10분 이상 11분 미만 발표에서 긴장하면 말이 빨라져 10분을 채우지 못했고, 자세히 설명하면 11분을 넘겼다. 시계를 보면 설명 흐름이 끊겼고, 연습과 실제 발표의 속도가 달랐다. 녹음·웹캠 녹화 후 다시 보는 점검이 오래 걸렸고 준비 전반에 약 10시간이 들었다고 기억한다. 한 사람의 경험이며 다른 대학생에게도 같은지는 추가 확인이 필요하다.

**③ 제작 결정 — design decision:** 설치 없는 PC·노트북 웹으로 만든다. 실시간 시간·속도 안내와 검토 구간 표시·재생·이전 연습 비교(F1–F6)는 구현했다. 다음으로 관찰 확인 → 당시 상황 질문 → 바꿔 볼 조건 선택 → 재연습 → 변화와 부담 확인(F13–F14, F11)을 만든다. 여기에 대본 이해·숙지 교차 확인과 자연스러운 대본 다듬기·교차검증(F15)을 핵심 피드백으로 더한다. 대본 수정·필수 내용 보존(F7–F10)은 그 안에서 고르는 조치로 연결한다. 군말·긴장 대화 예시는 설명용 가상 사례이며 E1에 추가하지 않는다. 감정 자동 판정·설치형 앱은 제외한다.

### 앞면·뒷면 일치 점검

- 한 문장 정의·③·5 Whys·통찰이 같은 순서(실시간 관리 어려움 → 점검 부담 → 무엇을 바꿀지 모름 → 다시 확인할 방법 없음)로 이어진다.
- 시간 초과와 미달을 모두 다루고, 10~11분 규칙·10분 30초 목표는 학생 확인 기록에서 가져왔다. 실제 종료 시각·감점 여부는 미확인이다.
- 10시간은 준비 전반에 대한 회고이며 영상 검토 시간이나 절감 가능 시간이 아니다.
- 경쟁사의 미확인 기능은 없다고 단정하지 않는다.
- 웹 서비스로 통일하고 현재 기능(F1–F6)과 개발 예정 기능(F7–F15)을 구분한다.
- 관찰·사용자 설명·원인 가설·조건 시험 결과를 구분한다.
