## 앞면

### 한 문장 문제 정의

발표를 앞둔 대학생은 혼자 연습할 때 내용을 말하면서 시간과 속도를 함께 살피기 어렵고, 시계를 보는 순간 설명 흐름이 끊긴다. 연습 뒤에는 녹음·영상을 처음부터 다시 보며 고칠 구간을 찾아야 하고, 찾아도 그 순간 왜 막혔는지(대본 숙지·기억·시간 확인)를 알 수 없어 약 10시간을 준비하고도 실제 발표에서 시간 초과와 미달을 반복한다.

### ① 상황

수업·팀 프로젝트 발표를 앞두고 집이나 빈 강의실에서 혼자 연습할 때 생긴다. 발표는 "10분 이상 11분 미만"처럼 범위가 정해져 있고 벗어나면 감점이다. 긴장하면 말이 빨라지고, 내용에 집중하면 시간이 얼마나 지났는지 놓치며, 시간을 보려고 화면이나 시계로 눈을 돌리면 설명하던 흐름이 끊긴다. 연습과 실제 발표의 말하기 속도가 달라서 연습 때 시간을 맞춰도 실제에서는 초과하거나 일찍 끝난다. 연습 뒤에는 휴대폰 녹음과 웹캠 녹화를 처음부터 다시 틀어 보며 고칠 부분을 찾는다. 최근에는 AI 도구로 발표 자료와 대본을 먼저 만들고 연습하는 경우가 많아, 대본은 금방 생기지만 문장을 숙지하지 못한 채 연습하게 되고 그 부분에서 말이 막힌다(팀원 진술). 영국 대학생 조사(HEPI 2025)에서는 92%가 생성형 AI를 쓰고 88%가 과제·평가에 쓰며 18%는 AI가 만든 문장을 과제에 그대로 넣었다. 국내에서는 2024년 한 해 검사된 문서 174만 건 중 55.9%에서 챗GPT 사용이 감지됐다(무하유).

### ② 고객

수업·팀 프로젝트에서 발표를 맡은 대학생이다. 발표 경험이 많지 않고, 짧은 준비 기간 안에 다른 사람 도움 없이 정해진 시간에 맞춰 혼자 점검하고 고쳐야 한다. 특히 AI 도구로 만든 자료·대본을 자기 말로 소화해 발표해야 하는 학생이 핵심 대상이다.

### ③ 근본 문제

발표 중에는 내용 전달에 집중하느라 속도와 시간을 동시에 점검할 수 없고, 시간을 확인하는 행동 자체가 흐름을 끊는다. 연습 뒤에는 녹음·시간 기록·고칠 내용이 따로 흩어져 있어 문제 구간을 직접 찾아야 하고, 찾아도 그 순간 어려웠던 이유(대본을 숙지하지 못했는지, 다음 내용이 떠오르지 않았는지, 시간을 신경 썼는지)가 어디에도 남지 않는다. 그래서 다음 연습에서 무엇을 바꿔야 할지 모른 채 "다시 외우자"는 다짐으로 같은 연습을 반복한다.

### ④ 영향

**그때 한 말·기분:** "되게 시간이 오래 걸렸어." 직접 녹음·녹화하고 다시 돌려 보는 과정이 부담이었고, 발표를 앞두고는 준비한 내용을 너무 일찍 끝내는 건 아닌지 계속 신경이 쓰였다(E1). 대본을 숙지하지 못한 채 발표를 앞두면 긴장이 커지고 자신감이 떨어진다(E2, 팀원 진술).

**시간·기회:** E1의 발표는 10분 이상 11분 미만을 벗어나면 감점이었다. 10분 30초를 목표로 스톱워치를 켜고 연습했지만 실제 발표에서 11분을 넘긴 적과 10분을 못 채운 적이 모두 있었다. 대사 암기, 녹음·웹캠 녹화, 반복 점검을 포함한 준비에 약 10시간이 들었다고 기억한다(회고 추정). 녹화를 점검할 때는 영상을 처음부터 끝까지 다시 봐야 했다. 대중 연설은 미국 성인 33.7%가 "두렵다·매우 두렵다"고 답한 공포(Chapman 2025)이고, 국내 대학 신입생 266명 조사(2025)에서는 그 불안이 청중의 평가보다 자기 수행을 통제하지 못할 것이라는 예측에서 더 크게 나왔다. MIT 미디어랩 실험(2025, 54명)에서 LLM으로 글을 쓴 참가자는 직후에도 자기 글을 정확히 인용하지 못했다. AI로 만든 대본을 "내 말"로 소화하지 못하는 문제의 실험 근거다.

## 뒷면

### 1. 관찰 정황

**P1 — 대상:** 10분 이상 11분 미만으로 끝내야 하는 수업·팀 프로젝트 발표를 맡은 대학생. 발표할 때 긴장하고, 혼자 연습하면서 내용·속도·제한 시간을 함께 관리해야 했다.

**P1 — 출처:** 종이 문제정의 기록과 본인 경험(E1), 학생 확인 후 기록(27eebf1).

**P2 — 대상:** AI 도구로 발표 자료와 대본을 먼저 만들고 그 대본으로 연습하는 대학생. 대본 문장을 완벽히 숙지하지 못한 채 연습해 특정 구간에서 말이 막히고, 발표를 앞두고 긴장과 자신감 저하를 겪는다.

**P2 — 출처:** 2026-10-29 팀원 진술(E2). 생성형 AI 사용 보편화(HEPI 2025, 무하유 2024)와 AI로 쓴 글을 기억하지 못하는 실험 결과(MIT 2025)가 뒷받침한다. 국내 대학생의 발표 대본 기준 비율은 미조사.

**E1 — 언제:** 대학교 응용 프로젝트 발표를 준비할 때. 10분보다 짧거나 11분 이상이면 감점이어서, 내용을 잘 전달하면서 정해진 범위 안에 끝내야 했다.

**E1 — 무슨 일:** 긴장하니 말이 빨라졌다. 발표 내용에 집중하다 보니 시간이 얼마나 지났고 얼마나 남았는지 확인하기 어려웠다. 시간을 확인하려고 화면이나 시계를 보면 설명하던 흐름이 끊겼고, 남은 시간을 알아도 어느 부분에서 속도를 조절해야 할지 바로 판단하기 어려웠다. 연습할 때와 실제 발표할 때 말하는 속도가 달랐다. 긴장해서 말이 빨라지면 10분을 채우지 못했고, 내용을 자세히 설명하다 보면 11분을 넘겼다. 연습 때 시간을 맞춰도 실제에서는 속도와 설명 분량이 달라져 범위 안에 마무리하기 어려웠다. 연습은 직접 녹음하고 웹캠으로 녹화한 뒤 다시 재생해 보며 점검했는데, 번거롭고 시간이 오래 걸렸다. 대사 암기까지 포함해 준비에 대략 10시간이 들었다고 기억한다.

**E1 — 어떻게 버텼나:** 대사를 외우고 휴대폰 스톱워치를 켠 채 대본을 읽으며 시간을 쟀다. 10분 30초를 목표로 잡고 길면 설명을 줄이고 짧으면 내용을 보충했다. 녹음·웹캠 녹화를 처음부터 다시 재생하며 점검했다.

**E1 — 기분:** 준비한 내용을 너무 일찍 끝내는 건 아닌지 신경이 쓰였다. 녹음·녹화 후 직접 확인하는 과정이 시간 부담이었다.

**E1 — 한 말:** “되게 시간이 오래 걸렸어”

**E1 — 출처:** 본인의 발표 준비·발표 경험. 종이 문제정의 기록을 옮기고 학생 확인 후 기록(27eebf1). 준비 시간 약 10시간은 회고 추정이며 실제 종료 시각과 감점 여부는 기록이 없다.

**E2 — 언제:** 2026-10-29 해커톤 팀 회의에서 최근 발표 준비 방식을 이야기할 때.

**E2 — 무슨 일:** AI 에이전트로 발표 자료와 대본을 만드는 경우가 많아졌다. 자료와 문장은 빨리 완성되지만 대본을 깊이 이해하거나 완벽히 숙지하지 못한 채 연습하게 되고, 숙지하지 못한 부분에서 대본이 떠오르지 않아 말이 막힌다. 대본이 글말이라 소리 내어 말하기도 어색하다. 스스로는 이해했다고 생각해도 막상 자기 말로 설명하면 원문과 달라지는 경우가 있다.

**E2 — 어떻게 버텼나:** 막힌 부분을 다시 외우거나 대본을 그대로 읽는다.

**E2 — 기분:** 대본을 숙지하지 못한 채 발표를 앞두면 긴장이 커지고 자신감이 떨어진다.

**E2 — 출처:** 2026-10-29 팀원 진술(decisions.md D18·D19). 몇 명 중 몇 명이 겪는지는 조사 전이다.

### 2. 5 Whys

**증상:** 연습을 반복해도 실제 발표에서 막힘과 시간 초과·미달이 되풀이되고, 연습 점검에 오래 걸리는 이유는 무엇인가?

1. 긴장하면 말이 빨라지고, 내용 전달에 집중하느라 경과 시간과 남은 시간을 확인하지 못한다. (E1)
2. 시간을 확인하려고 화면이나 시계를 보면 설명 흐름이 끊기고, 남은 시간을 알아도 어느 부분에서 조절할지 바로 판단하기 어렵다. (E1)
3. 연습 후에는 녹음·영상을 처음부터 다시 보며 문제 구간을 직접 찾아야 해서 점검에 시간이 오래 걸린다. (E1)
4. 문제 구간을 찾아도 그 순간 무엇이 어려웠는지(대본을 숙지하지 못했는지, 다음 내용이 떠오르지 않았는지, 시간을 신경 썼는지)는 녹음과 측정값만으로 알 수 없어 무엇을 바꿀지 스스로 정해야 한다. (E1·E2, MIT 2025)
5. 바꿔 본 것이 실제로 도움이 됐는지 같은 기준으로 전후를 비교하는 과정이 없어, "다음엔 잘 외워야지" 같은 다짐에 기대고 같은 연습을 반복한다. (E1·E2)

**근본 문제 — 앞면 ③에 반영:** 발표 중에는 내용 전달에 집중하느라 속도와 시간을 동시에 점검할 수 없고, 시간을 확인하는 행동 자체가 흐름을 끊는다. 연습 뒤에는 녹음·시간 기록·고칠 내용이 따로 흩어져 있어 문제 구간을 직접 찾아야 하고, 찾아도 그 순간 어려웠던 이유(대본을 숙지하지 못했는지, 다음 내용이 떠오르지 않았는지, 시간을 신경 썼는지)가 어디에도 남지 않는다. 그래서 다음 연습에서 무엇을 바꿔야 할지 모른 채 "다시 외우자"는 다짐으로 같은 연습을 반복한다.

5 Whys는 기획 분석 양식이며, 서비스가 사용자에게 다섯 번 묻는 대화 규칙이 아니다(서비스의 질문은 관찰 확인 외 항목당 기본 최대 3개).

### 4. 통찰 / INSIGHT

**① 관찰 — claim:** 시간 초과·미달은 "시간을 지키자"는 다짐과 반복 연습으로 해결되지 않았다. 시간을 확인하는 행동이 오히려 흐름을 끊었고, 연습 뒤에는 문제 구간을 직접 찾는 데 오래 걸렸으며, 찾은 구간에서 무엇을 바꿔 다시 연습할지는 아무 기록 없이 스스로 정해야 했다. 여기에 AI 도구로 대본을 쉽게 만들 수 있게 되면서 "대본이 있다"와 "대본을 자기 말로 소화했다"가 별개의 문제가 됐다. 그래서 측정값을 보여 주는 데서 멈추지 않고, 막힌 순간의 이유를 사용자에게 묻고 조건 하나를 바꿔 그 구간만 다시 연습해 전후를 비교하는 루프가 필요하다.

**② 근거 — evidence:** E1: 10분 이상 11분 미만 발표에서 10분 30초를 목표로 연습했지만 긴장하면 10분을 못 채웠고 자세히 설명하면 11분을 넘겼다. 시계를 보면 흐름이 끊겼고 연습과 실제의 속도가 달랐다. 녹음·웹캠 녹화를 처음부터 다시 보는 점검이 오래 걸려 준비 전반에 약 10시간이 들었다. E2: 팀원들은 AI 도구로 만든 대본을 숙지하지 못한 채 연습하다 특정 구간에서 막혔고, 이해했다고 생각한 부분도 자기 말로 설명하면 원문과 달라졌다. 공개 조사: 영국 대학생 88%가 과제·평가에 생성형 AI를 쓰고 18%는 AI 문장을 그대로 넣는다(HEPI 2025). LLM으로 쓴 글은 직후에도 자기 글을 인용하지 못했다(MIT 2025, 54명). 대중 연설 공포는 미국 성인 33.7%(Chapman 2025), 국내 신입생 266명은 "수행 통제감 부족"이 불안의 중심이었다(안상희 2025). 경쟁 서비스 직접 확인: PT샌드백은 목표 시간을 바꿔도 대본이 그대로였고, SayNow 피치 도구는 30초 요청에 49초 분량을 내놓고 직접 줄이라고 안내했다. 두 서비스 모두 막힌 이유를 묻고 조건을 바꿔 다시 시험하는 흐름은 확인되지 않았다.

**③ 제작 결정 — design decision:** 설치 없는 PC·노트북 웹으로 만든다. 실시간 시간·속도 안내, 검토 구간 표시·재생, 같은 조건의 이전 연습 비교(F1–F6)는 구현했다. 핵심 루프는 "관찰 확인 → 그때 무엇이 어려웠는지 질문(최대 3개, 건너뛰기 가능) → 바꿔 볼 조건 하나 선택 → 그 구간만 재연습 → 전후 비교"(F13–F14, F11)다. 여기에 대본 이해·숙지 교차 확인과 말하기 쉬운 문장으로 다듬기(F15)를 핵심 피드백으로 더하고, 대본 길이 조정·필수 내용 보존(F7–F10)은 그 안에서 필요할 때 고르는 조치로 연결한다. 점수·등급과 감정 자동 판정은 만들지 않고, 사용자의 설명과 측정된 관찰을 항상 구분해 기록한다.

### 앞면·뒷면 일치 점검

- 한 문장 정의·③·5 Whys·통찰이 같은 순서(실시간 관리 어려움 → 점검 부담 → 왜 막혔는지 모름 → 바꾼 뒤 확인할 방법 없음)로 이어진다.
- 시간 초과와 미달을 모두 다루고, 10~11분 규칙·10분 30초 목표는 학생 확인 기록(E1)에서 가져왔다.
- AI 도구로 만든 대본의 숙지 문제는 팀원 진술(E2)이며 비율은 대학생 설문으로 확인할 계획이다.
- 10시간은 준비 전반에 대한 회고이며 영상 검토 시간이나 절감 가능 시간이 아니다.
- 웹 서비스로 통일하고 현재 기능(F1–F6)과 개발 예정 기능(F7–F15)을 구분한다.
- 관찰·사용자 설명·원인 가설·조건 시험 결과를 구분해 기록한다.
