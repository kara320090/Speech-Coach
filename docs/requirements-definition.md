# 요구사항 정의서

## 2026-10-30 AI 처리 역할

새 대본 생성(F22)은 `/create-script.html`·`POST /api/scripts/generate`에서 Gemini 3.8 Flash로 처리한다. 사용자가 입력한 주제·근거 자료만 전송하며, 초안 확인 후 기존 기록을 보존한 새 버전으로 저장한다. 기존 대본의 개념 분석·쉬운 표현 수정·질문·답변 검토는 Qwen, 음성 전사는 faster-whisper로 처리한다. 자체 AI와 Gemini의 상태·실패는 독립적이며 자동 공급자 대체는 없다. API·설정은 [역할 분리 명세](gemini-coach.md)를 따른다.

## 2026-10-30 main 통합 상태

main의 다시봄 화면, TXT 불러오기, 구간 질문·조건 선택·재연습(S9), E2와 공개 조사 기록을 보존했다. 자체 AI 대본 코칭과 선택 전사, 영상 눈 깜빡임을 함께 제공한다. main의 F15는 대본 이해 교차 확인으로 유지하고, PR #3의 눈 깜빡임은 F21로 변경했다. 기존 문서의 미구현 표시는 당시 기록이며, 현재 상태는 이 절과 구현 범위 문서를 따른다. F13–F14 기본 흐름은 구현됐지만 전체 계획 수용 조건이 검증됐다는 뜻은 아니다.

**현재 구현 상태:** 자체 실행 텍스트 코칭과 음성 전사의 첫 구현이 추가됐다. 아래 전체 기획의 완료 조건과 구현된 부분은 [구현 범위](local-ai-implementation.md)에서 구분한다. 외부 AI Gateway와 브라우저 실시간 음성 인식은 제거/비활성화했다.


기준일: 2026-10-29. F1–F6은 기존 기능 ID를 유지한다. F7·F9–F12·F17–F20은 초기 구현과 후속 목표를 구분한다. F8·F13–F14 전체 흐름은 계획이다. F21–F16 기존 기능에 자체 전사 전환을 반영했다. “완료 조건”은 요구사항이지 모두 통과했다는 뜻이 아니다. 실제 증거는 [검증 계획·결과](validation-plan.md)에 기록한다.

## 2. 기능 요구사항

### F1 / FR-01 — 연습 준비

- 상태: 기존 코드 존재. `public/js/app.js`의 설정 화면·입력 검사.
- 입력: 목표 분·초, 허용 오차, 임박 안내 시점, 선택 속도 범위, 구간 계획, 녹음·영상·음성 인식 선택.
- 처리·출력: 잘못된 입력의 이유를 표시하고 유효한 설정으로 연습을 시작한다.
- 예외: 목표 없음·음수·최소 속도≥최대 속도·구간 형식 오류. 줄 오류는 줄 번호를 함께 표시한다.
- 완료 조건 AC-01: 잘못된 입력은 시작되지 않고, 유효 입력은 전달된 설정 그대로 연습 화면을 연다.

### F2 / FR-02 — 실시간 시간·속도 안내

- 상태: 기존 코드 존재.
- 입력: 시작·일시정지·다시 시작·종료, 선택 음성 인식 결과.
- 처리·출력: 정지 시간을 뺀 경과 시간, 남은 시간·초과 시간, 색과 글자로 시간 상태를 표시한다. 속도는 최근 20초의 한글 음절/분이다.
- 예외: 음성 인식 미지원·거부·오류·초기 자료 부족은 측정 불가/측정 중으로 구분한다.
- 완료 조건 AC-02: 목표를 넘으면 초과 상태가 나타나고, 미측정 속도를 0이나 추정 점수로 표시하지 않는다.

### F3 / FR-03 — 구간 계획과 실제 시간

- 상태: 기존 코드 존재. 사용자가 누르는 “다음 구간”을 기준으로 측정한다.
- 입력: 구간 이름·계획 시간, 구간 전환 시각, 연습 종료 시각.
- 처리·출력: 구간별 계획·실제·차이, 누적 지연, 진행하지 못한 구간을 표시한다.
- 예외: 계획 없음은 진행 속도를 판단하지 않음. 구간 이름이 중복되면 기존 비교가 혼동될 수 있어 R1에서 고정 ID로 보완한다.
- 완료 조건 AC-03: 진행 중 종료와 미진행을 구분하고, 자동 슬라이드 인식으로 측정한 것처럼 표현하지 않는다.

### F4 / FR-04 — 음성·선택 웹캠 기록

- 상태: 기존 코드 존재. 실제 장치 검증 필요.
- 입력: 마이크 권한, 선택 카메라 권한, 시작·정지 이벤트.
- 처리·출력: WAV 음성 및 선택 영상을 브라우저 IndexedDB에 보관하고 재생한다.
- 예외: 장치·권한·저장 실패를 안내하며 시간 측정은 계속한다. 브라우저 음성 인식은 외부 처리 가능성 때문에 비활성화한다. 자체 전사는 파일 불러오기에서 선택한다.
- 완료 조건 AC-04: 선택하지 않은 카메라는 사용하지 않으며, 기록 여부·저장 실패를 결과에서 확인할 수 있다.

### F5 / FR-05 — 검토 구간 자동 정리

- 상태: 기존 코드 존재. 규칙 기반 분석이며 LLM 평가가 아니다. 반복 표현은 같은 어절의 연속·30초 내 반복 규칙이며 “음·어” 군말의 정밀 판별과 같은 수준이 아니다. 군말 후보 집계는 F16으로 추가했다. 사용자 교정·질문은 여전히 F13 계획이다.
- 입력: 녹음, 선택 전사, 구간 기록.
- 처리·출력: 긴 침묵·반복 표현·속도 변화·구간 시간 차이의 위치·측정값·판정 근거를 표시하고 해당 시점으로 이동한다.
- 예외: 무음·짧은 녹음·인식 실패는 분석 불가 사유를 표시한다. 반복·침묵은 개선 후보이며 무조건 잘못된 발화가 아니다.
- 완료 조건 AC-05: 합성 음성의 알려진 침묵 위치를 찾고, 재생 이동과 결과 근거가 연결된다. 전사 시간은 근사값이라고 표시한다.

### F6 / FR-06 — 기록과 이전 연습 비교

- 상태: 기존 코드 존재.
- 입력: 같은 목표 시간·구간 계획의 이전 기록.
- 처리·출력: 실제 시간·목표 차이·측정된 속도·검토 항목 수를 나란히 표시한다. 기록 조회·삭제 기능을 제공한다.
- 예외: 비교 기록 없음·지표 미측정·저장 실패. 현재 비교 키에는 허용 오차·분석 버전이 없어 F11에서 보완한다.
- 완료 조건 AC-06: 측정하지 못한 지표는 비교 불가, 점수·개선율을 임의 생성하지 않음. 삭제 실패 전달은 추가 보완·검증 대상이다.

### F7 / FR-07 — 대본·필수 내용·버전 관리

- 상태: 초기 구현. 전체 AC 충족 여부와 남은 부분은 [구현 범위](local-ai-implementation.md)를 따른다.
- 입력: 직접 붙여넣은 대본과 별도의 근거 자료, 구간명, 필수 전달 항목, 근거 문장·수치·조건. 자료 제목·버전·출처를 사용자 입력으로 남긴다.
- 처리·출력: `projectId`, `scriptVersionId`, `sectionId`, `requirementId`와 자료 문단 ID를 부여하고 원본 버전을 보존한다. 대본과 근거 자료를 구분하며 AI 대본을 사실 검증된 자료로 표시하지 않는다.
- 예외: 빈 대본·누락된 필수 항목 근거·저장 실패. 첫 버전은 파일 추출·OCR을 지원하지 않는다.

- 입력: UTF-8 TXT 파일(1MB 이하)에서 불러오거나 직접 붙여넣은 뒤 편집한 대본, 구간명, 필수 전달 항목, 항목의 근거 문장·수치·조건.
- 구현된 부분: 대본 패널의 ‘대본 편집’에서 ‘TXT 파일 선택’ 또는 직접 붙여넣기 → 같은 입력란에서 확인·수정(불러온 파일명 표시). 예시 대본 그대로이거나 비어 있으면 바로 바꾸고, 직접 쓰거나 불러온 대본이 있으면 바꾸기 전에 확인한다 → 대본 패널의 문장 목록·핵심어 카드·진행 막대가 그 대본을 쓴다 → 녹화 시점의 대본을 기록의 `session.script`에, 불러온 파일명을 별도 메타데이터 `session.scriptFile`(`{ name, edited }`)에 저장 → ‘같은 조건으로 다시 연습’은 그 기록의 대본·파일명을 불러온다. 대본이 없는 이전 기록이면 지금 대본을 그대로 쓴다. 파일·대본은 서버나 외부 AI로 보내지 않는다.
- 예외: 빈 대본·누락된 필수 항목 근거·저장 실패. TXT 불러오기는 .txt가 아닌 형식, 1MB 초과, 빈 파일·공백뿐인 내용, UTF-8이 아닌 인코딩, 파일 읽기 실패를 안내하고 지금 대본을 지우지 않는다. 선택 창을 취소하면 그대로 둔다. PDF·DOCX·PPTX 추출·OCR은 지원하지 않는다.
- 완료 조건 AC-07: 원문과 수정문을 동시에 조회하고 수정안을 버려도 원문을 복원할 수 있다. 버전을 바꾸면 기존 연습의 연결은 유지된다.

### F8 / FR-08 — 최소·최대 시간과 개인 실측 기준

- 상태: 계획·미구현. 우선순위 P0.
- 입력: 최소·최대 발표 시간, 대본 버전, 실제 연습의 구간 시간·전사 및 사용자가 확인한 구간 대응.
- 처리·출력: 허용 범위, 실제 초과·미달, 개인 기준 예상 시간 및 계산에 사용한 자료를 표시한다.
- 예외: 최소>최대, 낮은 전사 품질, 인식 누락, 숫자·영어가 섞인 구간, 부분 연습뿐인 경우는 예측 제한을 표시한다.
- 완료 조건 AC-08: 최소·최대 경계를 포함해 범위 내/미달/초과를 판정한다. 실측 자료가 없으면 개인화된 예측이라고 표시하지 않는다. 예상과 실제는 별도 필드다.

### F9 / FR-09 — 쉬운 말·목표에 맞춘 대본 수정 제안

- 상태: 초기 구현. 전체 AC 충족 여부와 남은 부분은 [구현 범위](local-ai-implementation.md)를 따른다.
- 입력: F7 대본·근거·필수 항목, 선택한 개념·본인 설명. 시간 조정할 때만 F8의 목표·실측을 사용한다.
- 처리·출력: 쉬운 단어·짧은 문장·필요한 전문 용어 풀이, 수정 이유·자료 근거·변경 표시. 원문 보존, 선택하면 새 버전 생성.
- 예외: 자료 없음·모호한 개념·모델 실패·자원 한도. 일반적 풀이와 자료로 확인된 내용을 구분하고 근거 없는 사실을 채우지 않는다.
- 완료 조건 AC-09: 선택·거절·직접 수정·되돌리기, 개념·근거·원문·적용 상태 연결. 수치·부정·한계 등을 바꾼 의심은 F10으로 표시한다. 쉬운 문장이나 예상 시간 충족만으로 이해·발표 성공을 선언하지 않는다.

### F10 / FR-10 — 필수 내용 보존 검사

- 상태: 초기 구현. 전체 AC 충족 여부와 남은 부분은 [구현 범위](local-ai-implementation.md)를 따른다.
- 입력: 수정 전후 대본, 필수 항목 ID, 수치·단위·부정·조건을 포함한 제공 근거.
- 처리·출력: 항목별 유지/누락/변경 의심/판단 불가, 해당 문장과 근거를 표시한다.
- 예외: 동의어·요약 표현은 키워드 일치만으로 판정하지 않는다. 모호한 의미는 확인 필요로 남긴다. 원자료 자체의 진위를 보증하지 않는다.
- 완료 조건 AC-10: 필수 수치 누락·단위 변경·부정 반전·조건 삭제를 포함한 검증 세트에서 잘못된 제안을 “유지”로 확정하지 않으며, 변경 의심을 숨긴 채 확정 저장하지 않는다.

### F11 / FR-11 — 수정 항목별 재연습과 전체 확인

- 상태: 초기 구현. 전체 AC 충족 여부와 남은 부분은 [구현 범위](local-ai-implementation.md)를 따른다.
- 입력: 이전 연습 ID·수정 항목 ID·선택 대본 버전·재연습 결과. 조건 시험 ID·선택 조치·선택적 부담 응답도 연결한다. F18–F19의 같은 개념에 대한 자기 설명·동등 질문 답변과 도움 제공 여부를 연결한다.
- 처리·출력: 같은 항목의 해결/미해결/판단 불가와 발화 근거, 실제 시간 변화, 필수 내용 전달 상태를 표시한다. 구간 연습 이후 전체 연습을 별도로 수행한다.
- 예외: 목표·허용 범위·필수 항목·분석 방식이 바뀌면 조건 변경을 알리고 단순 개선으로 해석하지 않는다. 부분 연습을 전체 연습과 합산해 실측 결과로 만들지 않는다.
- 완료 조건 AC-11: 무엇을 고친 결과인지 추적되고, 전체 범위 충족은 전체 재연습 실측으로만 확정한다. 자동 판정과 사용자 확인 상태를 구분한다. F14의 의도한 조건 변화는 시험 대상으로 표시하고, 다른 조건 변화는 비교 제한으로 남긴다. 군말 빈도가 낮아져도 내용 누락·긴 침묵·부담 증가를 함께 보고 한 회차로 원인 해결을 확정하지 않는다. 자기 설명·동등 질문의 근거 충족과 도움 사용 여부를 따로 표시하며 군말 감소를 이해 향상으로 바꾸지 않는다.

### F12 / FR-12 — 결과 내보내기와 보관 관리

- 상태: 초기 구현. 전체 AC 충족 여부와 남은 부분은 [구현 범위](local-ai-implementation.md)를 따른다.
- 입력: 내보낼 프로젝트·버전·연습·검토 결과 선택.
- 처리·출력: 대본 버전·조건·측정값·근거·미측정 항목을 포함한 HTML/JSON 결과를 사용자가 저장한다. 영상 포함 여부는 별도 선택한다.
- 예외: 다운로드 실패·저장 용량 부족·삭제 실패. 브라우저 데이터 삭제 시 기록 손실 가능성을 안내한다.
- 완료 조건 AC-12: 내보낸 문서에서 예상·실제·미검증 상태가 구분되고, 선택하지 않은 영상·음성을 포함하지 않는다. 복원 기능은 별도 구현 전까지 지원한다고 쓰지 않는다. 원인 질문 답변·걱정의 원문은 기본 내보내기에서 제외하고 사용자가 선택한 요약만 포함한다.

### F13 / FR-13 — 관찰 확인과 상황·원인 질문

- 상태: 계획·미구현. 우선순위 P0. 상세: [코칭 설계](coaching-design.md).
- 입력: 검토 구간·재생·전사, 사용자 관찰 확인·교정, 선택적 상황 설명.
- 처리·출력: 관찰 사실과 본인 설명을 분리한다. 열린 질문으로 시작하고 답에 따라 구체적인 조건을 확인한다. 긴장을 언급한 경우에만 관련 후속 질문을 한다. 뜻을 모르겠다는 답변 또는 설명 근거의 차이가 있으면 F18로 연결하되 그것이 군말의 원인이라고 확정하지 않는다.
- 관찰 확인 선택지: 맞음 / 잘못 인식함 / 자연스러운 표현이거나 문제로 느끼지 않음. 첫 상황 질문은 “이 순간 어떤 점이 어려웠나요?” 같은 열린 질문이며 긴장을 유도하지 않는다.
- 예외: 오탐, 전사 누락(사용자가 재생 위치에 군말을 직접 추가), 자연스러운 표현, 문제로 느끼지 않음, 답변 없음·모르겠음·건너뛰기·중단. 답변 없음을 원인 없음으로 바꾸지 않는다. 같은 내용을 표현만 바꿔 반복 질문하지 않는다.
- 완료 조건 AC-13: 관찰 확인 외 질문은 항목당 기본 최대 3개다. 건너뛰어도 연습을 계속한다. 사용자에게 확인되지 않은 해석을 사실로 저장하지 않고 녹음에서 감정을 자동 판정하지 않는다.

### F14 / FR-14 — 연습 조건 설계와 시험

- 상태: 계획·미구현. 우선순위 P0. F13의 답변은 선택 사항이며 미확인 상태에서도 시작 가능하다.
- 입력: 사용자 설명 또는 원인 미확인, 선택한 조치, 기준 연습, 실제 발표에서 사용 가능한 단서·화면 제약.
- 처리·출력: 개념 풀이·근거 카드·쉬운 표현·질문 연습·핵심어 카드·전환 문장·구간 표시 중 설명에 맞는 1–2개 옵션과 이유를 제안한다. 선택한 하나만 적용하고 시험 ID, 바꾼 조건·유지 조건을 기록한다. F11에서 같은 구간 재연습과 필요 시 전체 연습을 연결한다.
- 예외: 제안 거절, 자료 부족, 효과 없음·악화, 여러 조건 동시 변경, 실제 발표에서 단서 사용 불가. 답변을 강요하지 않고 원래 조건으로 되돌릴 수 있다.
- 완료 조건 AC-14: 사용자 선택 없이 대본·화면을 바꾸지 않는다. 원문 보존, 단서에 사실 추가 금지, 반복 빈도·내용·시간·선택적 부담의 함께 보기, 무효·악화·판단 불가를 지원한다. 단서 없이 발표해야 한다면 단서를 줄인 전체 연습을 별도로 확인한다. 군말 0회·심리 원인 규명·극복 완료를 보장하지 않는다.

### F15 / FR-15 — 대본 이해·숙지 교차 확인과 자연스러운 대본 다듬기·교차검증

- 상태: 계획·미구현. 우선순위 P0(강조 피드백). 이해 확인 질문은 R1에서 로컬 규칙으로, 대본 다듬기·교차검증은 R3에서 F9–F10과 함께 구현한다. 상세: [코칭 설계 8절](coaching-design.md).
- 입력: F7 대본(선택: AI 도구로 만든 대본 표시), 연습 전사와 대본 구간 대응, 막힘·긴 침묵·반복·대본과 다른 발화 후보 구간, 이해 확인 응답, 자기 말 설명, 원문 기반 확인 질문 답변.
- 처리·출력: 후보 구간마다 “이 부분을 잘 이해하지 못한 것 같아요. 잘 이해한 게 맞나요?” 교차 확인 질문을 보이고 응답(이해함 / 잘 모르겠음 / 문장이 어색함 / 건너뛰기)에 따라 분기한다. 이해함이면 사용자 설명을 반영한 자연스러운 대본 다듬기 제안, 잘 모르겠음이면 원문 근거의 핵심 요약 후 재설명 요청, 문장이 어색함이면 구어체·문장 나누기 제안을 만든다. 원문·사용자 설명·수정안·재연습 발화의 4열 교차검증 비교표를 출력한다. “이해했다”는 응답은 자기 말 설명과 원문 기반 확인 질문(핵심 개념·순서·수치·조건)으로 다시 확인해 설명과 원문이 다른 부분을 표시한다.
- 예외: 대본 없음(F7 미입력)이면 이해 확인 질문만 하고 다듬기는 비활성. 전사와 대본 대응 실패, 사용자 설명과 원문의 의미 차이, 외부 AI 실패·한도·취소, 건너뛰기·중단.
- 완료 조건 AC-15: 사용자 응답 없이 “이해 부족”을 저장하지 않는다. “이해했다”는 응답과 설명·확인 답이 원문과 다르면 사용자가 속였다고 기록하지 않고 “설명과 원문이 다른 부분”으로 보여 준다. 확인 질문은 원문에 있는 내용만 묻는다. 선택 전에는 대본을 바꾸지 않고 적용·거절·되돌리기를 지원한다. 의미 차이는 어느 쪽이 맞다고 단정하지 않고 확인 필요로 표시한다. 수정안은 F10 보존 검사 결과(유지/누락/변경 의심/판단 불가)를 함께 보여 준 뒤에만 저장하며 원문에 없는 사실을 추가하지 않는다. 4열 비교에서 부분/전체 연습, 전사 품질을 표시한다. 이해·숙지 완료를 보장하지 않는다.

## 4. 기존 전사와 새 방향의 차이

파일 불러오기와 선택 글자 변환은 F16이다. Gateway 전사는 자체 worker로 대체했고 외부 브라우저 음성 인식은 비활성화했다. 자체 서버 처리와 브라우저 로컬 처리를 구분한다. [자체 AI 설계](local-ai-design.md).

## 5. 변경 관리

기능을 추가하거나 버튼 이름·저장 구조·전송 범위를 바꾸면 관련 F/FR/AC ID, 화면 명세, 검증 계획, `problem.yaml`, `progress.md`를 함께 갱신한다. `scenarios.yaml`은 실제 존재하는 화면의 흐름만 유지하고 미구현 흐름은 [화면 명세](screen-spec.md)에 둔다.

## 추가 구현 요구 F21–F16

### F21 / FR-21 — 브라우저 영상 눈 깜빡임 측정

- 입력: 저장된 영상·선택 분석. 출력: 횟수·분당 횟수·10초 구간·인식 누락률·계산 근거.
- 예외: 영상 없음·소리만 있는 파일·모델/지원/디코딩 실패·취소·얼굴 관측 부족·기준 구간 부족.
- 완료 조건 AC-21: 브라우저 로컬 처리, 고정 상수 표시, 인식 부족에서 수치 숨김, 기존 결과 보존, 검토 항목에서 영상 이동. 실제 사람 정확도는 추가 검증.

### F16 / FR-16 — 선택 음성 전사와 군말 후보 집계

- 전환 상태: F20 자체 전사로 전환했다. 외부 제공자 호출·키 읽기는 제거했으며 실제 사람 음성 품질은 미검증이다.

- 입력: 선택한 파일 전사 또는 기존 연습 전사. 출력: 후보 종류·횟수·전사 구간 근거.
- 예외: 자체 worker 없음·요청/누적 한도·전사 실패·전사 없음·군말 인식 누락·잘못된 구간 시간.
- 완료 조건 AC-16: 선택한 경우에만 자체 서버로 음성 전송, loopback 제한·오류 처리, 후보는 로컬 규칙 계산, 독립 토큰 판정·0/미측정 구분·구간 이동. 문맥 판단·정서 추정은 하지 않는다.

두 기능의 세부 상수·CSP·데이터·검증 연결은 [측정 명세](media-measurements.md)를 따른다. F7–F14가 구현됐다는 뜻은 아니다.


## 새 문제 대응 요구 F17–F20 — 초기 구현과 목표 수용 조건

### F17 / FR-17 — 낯선 개념 후보와 자료 근거 연결

- 상태: 초기 구현. 전체 AC 충족 여부와 남은 부분은 [구현 범위](local-ai-implementation.md)를 따른다.
- 입력: 대본·근거 자료·선택 구간·사용자가 표시한 낯선 표현.
- 처리·출력: 개념 ID, 원문 위치·인용, 근거 문단, 쉬운 풀이 초안과 확인 필요 항목. 어려움은 후보로 표시한다.
- 완료 조건 AC-17: 인용은 실제 입력 문장에 존재해야 한다. 자료가 없으면 근거 없음으로 남기고 잘 아는 표현은 제외할 수 있다. 모델의 풀이를 검증된 사실로 표시하지 않는다.

### F18 / FR-18 — 자기 말로 설명하는 이해 확인

- 상태: 초기 구현. 전체 AC 충족 여부와 남은 부분은 [구현 범위](local-ai-implementation.md)를 따른다.
- 입력: F17 개념·근거와 사용자의 자기 설명 또는 모르겠음·건너뛰기.
- 처리·출력: 설명에서 확인된 부분·보완할 부분·근거 문장·다음 한 단계. 상태는 근거와 부합/보완 필요/판단 불가/미응답이다.
- 완료 조건 AC-18: 군말·속도·표정·답변 길이로 이해를 판정하지 않는다. 뜻을 모르겠다고 하면 쉬운 설명을 바로 제공할 수 있고 질문을 반복 강요하지 않는다. 항목당 후속 질문은 기본 최대 3개이며 오답을 무조건 칭찬하지 않는다.

### F19 / FR-19 — 자료 기반 예상 질문과 답변 연습

- 상태: 초기 구현. 전체 AC 충족 여부와 남은 부분은 [구현 범위](local-ai-implementation.md)를 따른다.
- 입력: 대본·근거 자료·핵심 개념·사용자 답변·이전 연습 기록.
- 처리·출력: 왜·어떻게·예시·한계 질문, 기준 근거, 답변에서 확인된 내용·빠진 내용·보완 제안. 기준 답변은 답하기 전 기본 숨긴다.
- 완료 조건 AC-19: 자료 없는 질문은 답변 불가/추가 자료 필요로 남긴다. 말 바꾼 동등 질문의 결과와 도움 사용 여부를 F11에 연결하며 실제 청중 질문이나 이해 향상을 예측·보장하지 않는다.

### F20 / FR-20 — 공개 모델 자체 실행과 처리 상태

- 상태: 초기 구현. 전체 AC 충족 여부와 남은 부분은 [구현 범위](local-ai-implementation.md)를 따른다.
- 입력: 운영자가 준비한 모델·실행기, 사용자가 처리 요청한 최소 대본·근거·답변. 선택 전사는 음성 조각만 사용.
- 처리·출력: 자체 실행 모델의 구조화 결과, 모델·프롬프트 버전·처리 위치와 실패 이유. 초기 추가 학습은 없다.
- 완료 조건 AC-20: 외부 AI 제공자 호출·클라우드 자동 대체 없이 동작한다. 모델 없음·중단·한도·잘못된 출력에는 원문과 기본 연습을 보존한다. 자체 서버 처리도 브라우저 밖 전송임을 안내한다. 모델 미설치 환경에서 기존 S1–S4가 끝까지 동작한다.

공통 예외: 근거 없음·잘못된 인용·답변 없음·모델 없음·잘못된 JSON·기존 버전 응답·취소·자원 한도. 실패 상태를 낮은 이해 점수로 변환하지 않는다. 처리 순서·전송 경계는 [자체 AI 설계](local-ai-design.md)를 따른다.


## 현재 자체 AI 구현의 수용 상태

FR-07·09–12·17–20은 첫 구현이며 전체 AC가 모두 충족된 것은 아니다. [구현 범위](local-ai-implementation.md)의 표를 현재 판정 기준으로 사용한다. FR-08·13–14의 전체 흐름은 미구현이다.

FR-16의 과거 외부 전송·키 조건은 새 코드에 적용하지 않는다. `LOCAL_STT_URL`의 loopback worker, 크기·형식·누적 길이·오류·미설정 처리를 사용한다. NFR-02의 현재 전송은 자체 서버이며 NFR-08의 외부 AI 키는 읽지 않는다. NFR-11 외부 제공자 호출 금지·모델 없음 기본 기능 유지·추가 학습 없음은 현재 구조에 반영했다.

## FR-22 / AC-22 — 새 대본 생성

F22는 주제·선택 자료로 새 대본만 생성한다. 기존 대본 수정·답변 검토 요청은 이 API에서 거절한다. 2,400자 이내 초안을 직접 수정·확인한 뒤 적용하며 원본 버전과 답변 이력을 유지한다. 키 부재·한도·시간 초과·취소·잘못된 출력은 입력을 보존하고 자체 코칭에 영향을 주지 않아야 한다.

## FR-16 / AC-16 확장 — 메인 녹화 전사

메인 분석에서 자체 AI 전사를 선택하면 녹음을 먼저 보존한 뒤 전사·군말·속도까지 수행한다. 끄면 전송하지 않는다. 취소·서버 없음·빈 전사·부분 실패는 미측정 사유와 재생 가능한 원본을 남기며 0회·0음절/분으로 대신하지 않는다.
