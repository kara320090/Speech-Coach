# 요구사항 정의서

기준일: 2026-10-29. F1–F6은 기존 기능 ID를 유지한다. F7–F15는 새 기획이며 **미구현**이다. “완료 조건”은 요구사항이지 모두 통과했다는 뜻이 아니다. 실제 증거는 [검증 계획·결과](validation-plan.md)에 기록한다.

## 2. 기능 요구사항

### F1 / FR-01 — 연습 준비

- 상태: 기존 코드 존재. `public/js/app.js`의 설정 화면·입력 검사.
- 입력: 목표 분·초, 허용 오차, 임박 안내 시점, 선택 속도 범위, 구간 계획, 녹음·영상·음성 인식 선택.
- 처리·출력: 잘못된 입력의 이유를 표시하고 유효한 설정으로 연습을 시작한다.
- 예외: 목표 없음·음수·최소 속도≥최대 속도·구간 형식 오류. 줄 오류는 줄 번호를 함께 표시한다.
- 완료 조건 AC-01: 잘못된 입력은 시작되지 않고, 유효 입력은 전달된 설정 그대로 연습 화면을 연다.

### F2 / FR-02 — 실시간 시간·속도 안내

- 상태: 기존 코드 존재.
- 입력: 시작·일시정지·다시 시작·종료, 선택 음성 인식 결과.
- 처리·출력: 정지 시간을 뺀 경과 시간, 남은 시간·초과 시간, 색과 글자로 시간 상태를 표시한다. 속도는 최근 20초의 한글 음절/분이다.
- 예외: 음성 인식 미지원·거부·오류·초기 자료 부족은 측정 불가/측정 중으로 구분한다.
- 완료 조건 AC-02: 목표를 넘으면 초과 상태가 나타나고, 미측정 속도를 0이나 추정 점수로 표시하지 않는다.

### F3 / FR-03 — 구간 계획과 실제 시간

- 상태: 기존 코드 존재. 사용자가 누르는 “다음 구간”을 기준으로 측정한다.
- 입력: 구간 이름·계획 시간, 구간 전환 시각, 연습 종료 시각.
- 처리·출력: 구간별 계획·실제·차이, 누적 지연, 진행하지 못한 구간을 표시한다.
- 예외: 계획 없음은 진행 속도를 판단하지 않음. 구간 이름이 중복되면 기존 비교가 혼동될 수 있어 R1에서 고정 ID로 보완한다.
- 완료 조건 AC-03: 진행 중 종료와 미진행을 구분하고, 자동 슬라이드 인식으로 측정한 것처럼 표현하지 않는다.

### F4 / FR-04 — 음성·선택 웹캠 기록

- 상태: 기존 코드 존재. 실제 장치 검증 필요.
- 입력: 마이크 권한, 선택 카메라 권한, 시작·정지 이벤트.
- 처리·출력: WAV 음성 및 선택 영상을 브라우저 IndexedDB에 보관하고 재생한다.
- 예외: 장치·권한·저장 실패를 안내하며 시간 측정은 계속한다. 브라우저 음성 인식 사용 시 공급자에게 음성이 전송될 수 있음을 별도로 알린다.
- 완료 조건 AC-04: 선택하지 않은 카메라는 사용하지 않으며, 기록 여부·저장 실패를 결과에서 확인할 수 있다.

### F5 / FR-05 — 검토 구간 자동 정리

- 상태: 기존 코드 존재. 규칙 기반 분석이며 LLM 평가가 아니다. 반복 표현은 같은 어절의 연속·30초 내 반복 규칙이며 “음·어” 군말의 정밀 판별과 같은 수준이 아니다. 군말 후보·교정은 F13에서 다룬다.
- 입력: 녹음, 선택 전사, 구간 기록.
- 처리·출력: 긴 침묵·반복 표현·속도 변화·구간 시간 차이의 위치·측정값·판정 근거를 표시하고 해당 시점으로 이동한다.
- 예외: 무음·짧은 녹음·인식 실패는 분석 불가 사유를 표시한다. 반복·침묵은 개선 후보이며 무조건 잘못된 발화가 아니다.
- 완료 조건 AC-05: 합성 음성의 알려진 침묵 위치를 찾고, 재생 이동과 결과 근거가 연결된다. 전사 시간은 근사값이라고 표시한다.

### F6 / FR-06 — 기록과 이전 연습 비교

- 상태: 기존 코드 존재.
- 입력: 같은 목표 시간·구간 계획의 이전 기록.
- 처리·출력: 실제 시간·목표 차이·측정된 속도·검토 항목 수를 나란히 표시한다. 기록 조회·삭제 기능을 제공한다.
- 예외: 비교 기록 없음·지표 미측정·저장 실패. 현재 비교 키에는 허용 오차·분석 버전이 없어 F11에서 보완한다.
- 완료 조건 AC-06: 측정하지 못한 지표는 비교 불가, 점수·개선율을 임의 생성하지 않음. 삭제 실패 전달은 추가 보완·검증 대상이다.

### F7 / FR-07 — 대본·필수 내용·버전 관리

- 상태: 일부 구현(2026-10-29 대본 입력·표시·기록 연결). 필수 항목·버전 ID·수정안은 계획·미구현. 우선순위 P0.
- 입력: UTF-8 TXT 파일(1MB 이하)에서 불러오거나 직접 붙여넣은 뒤 편집한 대본, 구간명, 필수 전달 항목, 항목의 근거 문장·수치·조건.
- 구현된 부분: 대본 패널의 ‘대본 편집’에서 ‘TXT 파일 선택’ 또는 직접 붙여넣기 → 같은 입력란에서 확인·수정(불러온 파일명 표시). 예시 대본 그대로이거나 비어 있으면 바로 바꾸고, 직접 쓰거나 불러온 대본이 있으면 바꾸기 전에 확인한다 → 대본 패널의 문장 목록·핵심어 카드·진행 막대가 그 대본을 쓴다 → 녹화 시점의 대본을 기록의 `session.script`에, 불러온 파일명을 별도 메타데이터 `session.scriptFile`(`{ name, edited }`)에 저장 → ‘같은 조건으로 다시 연습’은 그 기록의 대본·파일명을 불러온다. 대본이 없는 이전 기록이면 지금 대본을 그대로 쓴다. 파일·대본은 서버나 외부 AI로 보내지 않는다.
- 처리·출력: `projectId`, `scriptVersionId`, `sectionId`, `requirementId`를 부여하고 원본 버전을 보존한다.
- 예외: 빈 대본·누락된 필수 항목 근거·저장 실패. TXT 불러오기는 .txt가 아닌 형식, 1MB 초과, 빈 파일·공백뿐인 내용, UTF-8이 아닌 인코딩, 파일 읽기 실패를 안내하고 지금 대본을 지우지 않는다. 선택 창을 취소하면 그대로 둔다. PDF·DOCX·PPTX 추출·OCR은 지원하지 않는다.
- 완료 조건 AC-07: 원문과 수정문을 동시에 조회하고 수정안을 버려도 원문을 복원할 수 있다. 버전을 바꾸면 기존 연습의 연결은 유지된다.

### F8 / FR-08 — 최소·최대 시간과 개인 실측 기준

- 상태: 계획·미구현. 우선순위 P0.
- 입력: 최소·최대 발표 시간, 대본 버전, 실제 연습의 구간 시간·전사 및 사용자가 확인한 구간 대응.
- 처리·출력: 허용 범위, 실제 초과·미달, 개인 기준 예상 시간 및 계산에 사용한 자료를 표시한다.
- 예외: 최소>최대, 낮은 전사 품질, 인식 누락, 숫자·영어가 섞인 구간, 부분 연습뿐인 경우는 예측 제한을 표시한다.
- 완료 조건 AC-08: 최소·최대 경계를 포함해 범위 내/미달/초과를 판정한다. 실측 자료가 없으면 개인화된 예측이라고 표시하지 않는다. 예상과 실제는 별도 필드다.

### F9 / FR-09 — 목표에 맞춘 대본 수정 제안

- 상태: 계획·미구현. 우선순위 P1.
- 입력: F7 대본·필수 항목, F8 목표 범위·실측 근거, 사용자가 제공한 보완 자료.
- 처리·출력: 중복 축약 또는 근거 있는 보완 문장, 수정 이유, 바뀐 부분, 예상 시간 변화를 제안한다. 원문에 자동 덮어쓰지 않는다.
- 예외: 보완 자료 부족이면 필요한 예시·근거를 요청하고 허구를 채우지 않는다. API 실패·비용 한도 도달 시 원문과 기존 분석을 보존한다.
- 완료 조건 AC-09: 사용자가 제안을 선택·거절·수정·되돌릴 수 있고, 모든 제안에 근거 구간과 적용 상태가 남는다. 예상 시간 충족만으로 완료 처리하지 않는다.

### F10 / FR-10 — 필수 내용 보존 검사

- 상태: 계획·미구현. 우선순위 P1.
- 입력: 수정 전후 대본, 필수 항목 ID, 수치·단위·부정·조건을 포함한 제공 근거.
- 처리·출력: 항목별 유지/누락/변경 의심/판단 불가, 해당 문장과 근거를 표시한다.
- 예외: 동의어·요약 표현은 키워드 일치만으로 판정하지 않는다. 모호한 의미는 확인 필요로 남긴다. 원자료 자체의 진위를 보증하지 않는다.
- 완료 조건 AC-10: 필수 수치 누락·단위 변경·부정 반전·조건 삭제를 포함한 검증 세트에서 잘못된 제안을 “유지”로 확정하지 않으며, 변경 의심을 숨긴 채 확정 저장하지 않는다.

### F11 / FR-11 — 수정 항목별 재연습과 전체 확인

- 상태: 계획·미구현. 우선순위 P0.
- 입력: 이전 연습 ID·수정 항목 ID·선택 대본 버전·재연습 결과. 조건 시험 ID·선택 조치·선택적 부담 응답도 연결한다.
- 처리·출력: 같은 항목의 해결/미해결/판단 불가와 발화 근거, 실제 시간 변화, 필수 내용 전달 상태를 표시한다. 구간 연습 이후 전체 연습을 별도로 수행한다.
- 예외: 목표·허용 범위·필수 항목·분석 방식이 바뀌면 조건 변경을 알리고 단순 개선으로 해석하지 않는다. 부분 연습을 전체 연습과 합산해 실측 결과로 만들지 않는다.
- 완료 조건 AC-11: 무엇을 고친 결과인지 추적되고, 전체 범위 충족은 전체 재연습 실측으로만 확정한다. 자동 판정과 사용자 확인 상태를 구분한다. F14의 의도한 조건 변화는 시험 대상으로 표시하고, 다른 조건 변화는 비교 제한으로 남긴다. 군말 빈도가 낮아져도 내용 누락·긴 침묵·부담 증가를 함께 보고 한 회차로 원인 해결을 확정하지 않는다.

### F12 / FR-12 — 결과 내보내기와 보관 관리

- 상태: 계획·미구현. 우선순위 P1. 기존 기록 삭제는 F6에 존재한다.
- 입력: 내보낼 프로젝트·버전·연습·검토 결과 선택.
- 처리·출력: 대본 버전·조건·측정값·근거·미측정 항목을 포함한 HTML/JSON 결과를 사용자가 저장한다. 영상 포함 여부는 별도 선택한다.
- 예외: 다운로드 실패·저장 용량 부족·삭제 실패. 브라우저 데이터 삭제 시 기록 손실 가능성을 안내한다.
- 완료 조건 AC-12: 내보낸 문서에서 예상·실제·미검증 상태가 구분되고, 선택하지 않은 영상·음성을 포함하지 않는다. 복원 기능은 별도 구현 전까지 지원한다고 쓰지 않는다. 원인 질문 답변·걱정의 원문은 기본 내보내기에서 제외하고 사용자가 선택한 요약만 포함한다.

### F13 / FR-13 — 관찰 확인과 상황·원인 질문

- 상태: 계획·미구현. 우선순위 P0. 상세: [코칭 설계](coaching-design.md).
- 입력: 검토 구간·재생·전사, 사용자 관찰 확인·교정, 선택적 상황 설명.
- 처리·출력: 관찰 사실과 본인 설명을 분리한다. 열린 질문으로 시작하고 답에 따라 구체적인 조건을 확인한다. 긴장을 언급한 경우에만 관련 후속 질문을 한다.
- 관찰 확인 선택지: 맞음 / 잘못 인식함 / 자연스러운 표현이거나 문제로 느끼지 않음. 첫 상황 질문은 “이 순간 어떤 점이 어려웠나요?” 같은 열린 질문이며 긴장을 유도하지 않는다.
- 예외: 오탐, 전사 누락(사용자가 재생 위치에 군말을 직접 추가), 자연스러운 표현, 문제로 느끼지 않음, 답변 없음·모르겠음·건너뛰기·중단. 답변 없음을 원인 없음으로 바꾸지 않는다. 같은 내용을 표현만 바꿔 반복 질문하지 않는다.
- 완료 조건 AC-13: 관찰 확인 외 질문은 항목당 기본 최대 3개다. 건너뛰어도 연습을 계속한다. 사용자에게 확인되지 않은 해석을 사실로 저장하지 않고 녹음에서 감정을 자동 판정하지 않는다.

### F14 / FR-14 — 연습 조건 설계와 시험

- 상태: 계획·미구현. 우선순위 P0. F13의 답변은 선택 사항이며 미확인 상태에서도 시작 가능하다.
- 입력: 사용자 설명 또는 원인 미확인, 선택한 조치, 기준 연습, 실제 발표에서 사용 가능한 단서·화면 제약.
- 처리·출력: 핵심어 카드·전환 문장·구간 표시 등 1–2개 옵션과 이유를 제안한다. 선택한 하나만 적용하고 시험 ID, 바꾼 조건·유지 조건을 기록한다. F11에서 같은 구간 재연습과 필요 시 전체 연습을 연결한다.
- 예외: 제안 거절, 자료 부족, 효과 없음·악화, 여러 조건 동시 변경, 실제 발표에서 단서 사용 불가. 답변을 강요하지 않고 원래 조건으로 되돌릴 수 있다.
- 완료 조건 AC-14: 사용자 선택 없이 대본·화면을 바꾸지 않는다. 원문 보존, 단서에 사실 추가 금지, 반복 빈도·내용·시간·선택적 부담의 함께 보기, 무효·악화·판단 불가를 지원한다. 단서 없이 발표해야 한다면 단서를 줄인 전체 연습을 별도로 확인한다. 군말 0회·심리 원인 규명·극복 완료를 보장하지 않는다.

### F15 / FR-15 — 대본 이해·숙지 교차 확인과 자연스러운 대본 다듬기·교차검증

- 상태: 계획·미구현. 우선순위 P0(강조 피드백). 이해 확인 질문은 R1에서 로컬 규칙으로, 대본 다듬기·교차검증은 R3에서 F9–F10과 함께 구현한다. 상세: [코칭 설계 8절](coaching-design.md).
- 입력: F7 대본(선택: AI 도구로 만든 대본 표시), 연습 전사와 대본 구간 대응, 막힘·긴 침묵·반복·대본과 다른 발화 후보 구간, 이해 확인 응답, 자기 말 설명, 원문 기반 확인 질문 답변.
- 처리·출력: 후보 구간마다 “이 부분을 잘 이해하지 못한 것 같아요. 잘 이해한 게 맞나요?” 교차 확인 질문을 보이고 응답(이해함 / 잘 모르겠음 / 문장이 어색함 / 건너뛰기)에 따라 분기한다. 이해함이면 사용자 설명을 반영한 자연스러운 대본 다듬기 제안, 잘 모르겠음이면 원문 근거의 핵심 요약 후 재설명 요청, 문장이 어색함이면 구어체·문장 나누기 제안을 만든다. 원문·사용자 설명·수정안·재연습 발화의 4열 교차검증 비교표를 출력한다. “이해했다”는 응답은 자기 말 설명과 원문 기반 확인 질문(핵심 개념·순서·수치·조건)으로 다시 확인해 설명과 원문이 다른 부분을 표시한다.
- 예외: 대본 없음(F7 미입력)이면 이해 확인 질문만 하고 다듬기는 비활성. 전사와 대본 대응 실패, 사용자 설명과 원문의 의미 차이, 외부 AI 실패·한도·취소, 건너뛰기·중단.
- 완료 조건 AC-15: 사용자 응답 없이 “이해 부족”을 저장하지 않는다. “이해했다”는 응답과 설명·확인 답이 원문과 다르면 사용자가 속였다고 기록하지 않고 “설명과 원문이 다른 부분”으로 보여 준다. 확인 질문은 원문에 있는 내용만 묻는다. 선택 전에는 대본을 바꾸지 않고 적용·거절·되돌리기를 지원한다. 의미 차이는 어느 쪽이 맞다고 단정하지 않고 확인 필요로 표시한다. 수정안은 F10 보존 검사 결과(유지/누락/변경 의심/판단 불가)를 함께 보여 준 뒤에만 저장하며 원문에 없는 사실을 추가하지 않는다. 4열 비교에서 부분/전체 연습, 전사 품질을 표시한다. 이해·숙지 완료를 보장하지 않는다.

## 4. 번호 미배정 구현 기능

영상·소리 파일 불러오기와 선택 글자 변환(`/import.html`, `POST /api/transcribe`)은 `9d2a10b`에 코드가 있다. 작성자가 F 번호를 배정하지 않았으므로 이 문서도 FR/AC 번호를 새로 만들지 않는다. 요구·예외·검증은 [영상 불러오기 문서](import-feature.md)를 따른다. 번호를 정하면 추적표·화면 명세·검증 계획을 함께 갱신한다.

## 5. 변경 관리

기능을 추가하거나 버튼 이름·저장 구조·전송 범위를 바꾸면 관련 F/FR/AC ID, 화면 명세, 검증 계획, `problem.yaml`, `progress.md`를 함께 갱신한다. `scenarios.yaml`은 실제 존재하는 화면의 흐름만 유지하고 미구현 흐름은 [화면 명세](screen-spec.md)에 둔다.
