# Speech-Coach (발표 연습 코치)

SUMTECH 2026 루프톤 팀 저장소입니다. 발표를 준비하는 대학생이 혼자 연습하면서 **연습 중에는 시간·속도를 확인**하고, **연습 뒤에는 처음부터 다시 보지 않고 확인할 구간부터** 볼 수 있게 돕는 웹 서비스입니다.

- 문제정의: [docs/problem.yaml](docs/problem.yaml)
- 사용자 핵심 흐름: [docs/scenarios.yaml](docs/scenarios.yaml)
- 진행 기록: [progress.md](progress.md)

## 사용 흐름

시간 계획 설정 → 발표 연습 → 실시간 상태 확인 → 자동으로 표시된 구간 검토 → 재연습 → 변화 확인

1. **연습 준비**: 목표 시간(분·초, 매번 직접 입력), 허용 오차, 임박 알림 기준, 목표 속도 범위(선택), 구간별 시간 계획(선택), 소리 기록·웹캠 영상 기록·음성 인식 사용 여부를 정합니다.
2. **연습 중**: 경과 시간·남은 시간, 시간 상태(여유 / 임박 / 초과, 색과 글자), 구간 진행, (음성 인식을 켠 경우) 말하기 속도를 보여 줍니다. 일시정지·다음 구간·종료 버튼이 있습니다.
3. **결과**: 총 연습 시간, 목표와의 차이(초과 / 일찍 끝남 / 허용 오차 안), 평균 속도, 구간별 계획과 실제, **다시 확인해 볼 구간 목록**(누르면 녹음·영상의 그 위치로 이동)을 보여 줍니다.
4. **비교**: 같은 목표 시간·구간 계획으로 한 이전 연습이 있으면 측정값을 나란히 보여 줍니다. 없으면 "아직 비교할 이전 기록이 없어요"라고 표시합니다. 점수나 개선율은 만들지 않습니다.

## 계산 기준

| 항목 | 기준 |
| ---- | ---- |
| 시간 | 화면·결과·구간 비교 모두 정수 초로 계산. 일시정지한 시간은 연습 시간과 기록에서 제외 |
| 속도 단위 | **분당 음절** = 한글 음절(가–힣) 글자 수 ÷ 시간(분). 쉬는 시간도 시간에 포함 |
| 실시간 속도 | 최근 20초 동안의 음절 수 기준. 연습 시작 후 10초 동안은 "측정 중"으로만 표시 |
| 평균 속도 | 인식된 전체 음절 수 ÷ 전체 연습 시간 |
| 긴 침묵 | 100ms 단위 소리 크기(RMS)가 기준 이하인 상태가 3초 이상. 기준 = 이 녹음의 하위 10% 크기 + (상위 10% − 하위 10%) × 0.2. 소리가 거의 없는 녹음은 "소리 없음"으로 처리 |
| 속도 변화 | 10초 구간 속도가 평균보다 30% 이상 차이. 말이 3음절 미만인 구간은 제외, 판단 가능한 구간이 3개 미만이면 판단하지 않음 |
| 반복 표현 | 같은 어절이 바로 이어서 2번 이상, 또는 같은 어절(2글자 이상)이 30초 안에 3번 이상 |
| 구간 시간 | 연습 중 '다음 구간'을 누른 시점 기준. 진행 판단은 구간 계획이 있을 때만 제공 |

속도·반복 표현의 시간 위치는 브라우저 음성 인식 결과가 도착한 시점으로 추정한 값이라 정확하지 않을 수 있고, 화면에도 그렇게 안내합니다. 측정할 수 없는 상태(음성 인식 꺼짐·미지원·권한 거부·오류)에서는 숫자를 보여 주지 않고 이유를 적습니다.

## 개인정보

- 녹음(WAV), 웹캠 영상, 분석 결과, 연습 기록은 **이 브라우저의 IndexedDB에만 저장**하고 서버로 보내지 않습니다. 서버는 정적 파일과 `/__health`만 제공합니다.
- **음성 인식은 기본으로 꺼져 있습니다.** 켜면 브라우저(예: Chrome)가 제공하는 음성 인식 서비스로 음성이 전송될 수 있다고 연습 준비 화면에 안내합니다.
- 소리 기록 시 브라우저의 자동 음량 조절·잡음 억제·에코 제거는 꺼서 소리 크기 기준 분석이 흔들리지 않게 합니다.

## 구현 설계

- 서버: Node 내장 `http`만 사용하는 `server.js` (외부 패키지 없음). `public/`을 서빙하고 `GET /__health`가 `{"status":"ok","releaseId":…}`를 200으로 응답합니다. 없는 주소는 404.
- 화면: `public/` 의 바닐라 JS(ES 모듈). 해시 주소(`#/`, `#/practice`, `#/result/ID`, `#/history`)로 화면을 바꿉니다.
  - `js/time.js` 시간 표기·입력, `js/plan.js` 구간 계획, `js/analysis.js` 침묵·속도·반복·비교 분석, `js/wav.js` 16kHz WAV 변환, `js/recorder.js` 마이크·웹캠·음성 인식, `js/storage.js` IndexedDB 저장, `js/app.js` 화면
- 소리는 Web Audio로 받아 16kHz 모노 WAV로 만들어(어느 위치로든 바로 이동 가능), 웹캠 영상은 `MediaRecorder`(webm)로 기록합니다.
- 로그인·DB·AI 호출은 없습니다. 그래서 `docker-compose.yml`에는 `app` 서비스 하나만 있습니다.

## 설치·빌드·실행

```bash
# 로컬(Node 22 이상, 설치할 패키지 없음)
node server.js          # http://localhost:3000

# docker (주최 측 실행과 같은 방식)
docker compose up --build   # http://localhost:3000, 상태 확인: http://localhost:3000/__health
```

마이크·웹캠은 `localhost` 또는 HTTPS 주소에서만 브라우저가 허용합니다.

## 테스트

```bash
node --test                 # 단위 테스트(시간·구간 계획·분석·WAV·서버)
cd e2e && npm install && npx playwright install chromium
npx playwright test         # docs/scenarios.yaml의 S1~S4 흐름 (마이크가 없어도 되는 부분)
npx playwright test -c media.config.ts   # 가짜 마이크·웹캠 장치로 기록·구간 이동·실패 상황 확인
```

`media.config.ts` 검사는 크롬의 가짜 장치(`fixtures/fake-speech.wav`를 마이크로 들려줌)와 가짜 `SpeechRecognition`을 씁니다. 실제 사람의 목소리·마이크·카메라·음성 인식 서비스로 한 검사가 아닙니다.
