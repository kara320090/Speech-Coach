# Speech-Coach — 발표 연습 코치

SUMTECH 2026 팀의 **설치 없이 사용하는 PC·노트북 웹 서비스**입니다. 발표 시간·속도를 확인하고 녹음에서 다시 검토할 구간을 찾습니다. 이후 당시 상황을 짧은 질문으로 확인하고, 핵심어 단서·화면·연습 조건을 선택해 바꾼 뒤 재연습에서 확인하는 흐름으로 확장합니다. 대본 수정·필수 내용 보존도 필요한 조치로 연결합니다.

## 현재 제공 기능과 개발 예정 기능

| 범위 | 상태 |
| --- | --- |
| F1–F6: 목표·구간 계획, 시간·선택 속도 안내, 음성·선택 웹캠 기록, 검토 구간 재생, 같은 조건의 이전 기록 비교 | 코드 존재. 단위 테스트(전체 40개, `9d2a10b` 기준) 통과. CI에서 Docker·health·기존 시나리오 4개 통과 확인. 실제 장치·공개 배포 검증은 별도 필요 |
| 영상·소리 파일 불러오기(`/import.html`)와 선택 글자 변환(`/api/transcribe`) | 코드 존재, **기능 번호 미배정**. 가짜 게이트웨이 단위 검사만 확인, 실제 AI Gateway 호출·Render 배포는 미검증. [설명](docs/import-feature.md) |
| F7 일부: 발표 대본 TXT 불러오기(UTF-8, 1MB 이하)·붙여넣기·편집, 연습 화면 대본 표시, 연습 기록별 대본 저장·같은 조건 재연습 불러오기 | 코드 존재. 브라우저 안에서만 읽고 저장(서버 전송 없음). 단위·브라우저 자동 검사 통과, 실제 사용자 검증 전 |
| F7 나머지–F14: 필수 항목·버전·시간 기준·수정·보존·재점검·내보내기, 상황 확인 질문·연습 조건 시험 | 기획·요구사항 작성 완료, **미구현** |

핵심 흐름(개발 예정): **연습 → 관찰 확인 → 당시 상황 질문 → 바꿔 볼 조건 선택 → 재연습 → 변화와 부담 확인**. 군말을 “줄이세요”라고 지적하는 데서 끝내지 않고, 사용자가 설명한 어려움에 맞춰 핵심어 단서·전환 문장·화면 표시·연습 범위 같은 조건을 하나씩 바꿔 시험합니다. 질문은 건너뛸 수 있고, AI가 마음속 원인을 알아냈다고 표시하지 않습니다. 상세는 [코칭 설계](docs/coaching-design.md).

모바일 네이티브 앱·데스크톱 설치형 앱을 만들지 않습니다. 타이머·한국어·회차 비교만을 경쟁사에 없는 기능으로 주장하지 않습니다.

## 현재 구조

Node.js 정적 서버와 순수 JavaScript 웹 화면입니다. 현재 서버 데이터베이스·회원가입·대본 수정용 LLM 호출은 없습니다. `server.js`가 `public/`, `GET /__health`, 그리고 영상 불러오기에서 사용자가 글자 변환을 켰을 때만 쓰는 `POST /api/transcribe`(AI Gateway 음성 인식 중계)를 제공합니다.

음성·선택 영상·결과는 브라우저 IndexedDB에 저장합니다. 브라우저 데이터 삭제 또는 저장 실패 시 기록이 사라질 수 있습니다. 선택형 브라우저 음성 인식은 제공 업체로 음성이 전송될 수 있으므로 별도로 안내합니다. 영상 불러오기의 글자 변환을 켜면 약 20초 WAV 조각이 우리 서버를 거쳐 외부 음성 인식으로 전송됩니다(영상 파일은 전송하지 않음). 대본 수정·코칭 답변의 외부 AI 전송은 구현되지 않았으며, 계획상 상황 질문 답변 원문은 기본 로컬 보관입니다.

## 로컬 개발 실행

Node.js 22 이상이 필요합니다. 현재 외부 npm 의존성이나 별도 빌드 단계는 없습니다. 이는 개발자 실행 방법이며 서비스 이용자에게 설치를 요구한다는 뜻이 아닙니다.

```sh
npm start
```

브라우저에서 `http://localhost:3000`을 엽니다. 마이크·웹캠·음성 인식 지원은 브라우저에 따라 다릅니다. 실제 외부 제공 환경은 HTTPS로 검증해야 합니다.

```sh
npm test
```

단위 테스트 49개가 포함되어 있습니다(영상 불러오기 13개, 대본 불러오기 9개 포함). 기존 S1–S4의 브라우저 흐름은 CI에서 4개 통과했습니다. 별도의 가짜 장치·가짜 음성 인식 검사 파일도 추가됐지만 이 CI는 그것을 실행하지 않습니다. 실제 사람의 마이크·카메라·음성 인식 품질은 미검증입니다. E2E 실행 방법은 [기본 구현 문서](docs/current-implementation.md)를 참고하세요.

## Docker 실행 구성

```sh
docker compose up --build
```

`app` 서비스 하나로 3000번 포트를 엽니다. 기존 commit `625b942`의 [CI 실행](https://github.com/kara320090/Speech-Coach/actions/runs/40866156494)에서 Docker 기동·health·시나리오 4개 통과를 확인했습니다. 이번 로컬 작업에서 Docker를 직접 실행한 것은 아닙니다. 실제 배포 URL은 아직 이 문서에 확인되지 않았습니다.

## 환경변수

| 이름 | 현재 용도 | 설정 위치 |
| --- | --- | --- |
| `PORT` | Node 서버 포트, 기본 3000 | 서버 실행 환경. 제공 compose는 3000 고정 구성 |
| `RELEASE_ID` | `/__health`의 releaseId, 기본 dev | 서버 실행 환경 또는 Docker build arg·compose 환경 |
| `AI_GATEWAY_API_KEY` | 영상 불러오기의 글자 변환용 AI Gateway 키(비밀값). 없으면 글자 변환만 꺼짐 | 서버 환경변수, Render Environment, GitHub Secrets |
| `TRANSCRIBE_MODEL` | (선택) 음성 인식 모델, 기본 `google/gemini-3.5-transcribe` | 같은 곳 |
| `TRANSCRIBE_TOTAL_SECONDS` | (선택) 서버가 켜져 있는 동안 글자로 바꿀 소리 길이 합(초), 기본 3600 | 같은 곳 |
| `AI_GATEWAY_URL` | (선택) AI Gateway 주소, 기본 `https://ai-gateway.vercel.sh` | 같은 곳 |

`.env.example`은 안내용이며 현재 Node 서버는 `.env`를 자동으로 읽지 않습니다. 실제 배포 시 `RELEASE_ID`에 배포 commit을 넣고 응답과 대조해야 합니다. 영상 불러오기의 글자 변환이 `AI_GATEWAY_API_KEY` 등을 읽습니다(아래 표, 자세한 내용은 [영상 불러오기 문서](docs/import-feature.md)). 키는 서버 환경변수로만 넣고 저장소·화면에는 두지 않습니다.

## 영상·소리 파일 불러오기와 Render 배포 (추가 구현)

이미 녹음·녹화한 파일(mp4, m4a, mp3, wav, webm)을 `/import.html`에서 불러오면 소리만 브라우저 안에서 꺼내 긴 침묵을 찾고, 학생이 직접 켠 경우에만 소리 조각(약 20초 WAV)을 서버의 `/api/transcribe`를 거쳐 AI Gateway로 보내 글자로 바꿉니다. 영상 파일은 서버로 보내지 않습니다. 이 기능은 위 기획의 F1–F14 번호에 아직 넣지 않았습니다. 처리 흐름·전송 범위·API·환경변수·Render 배포 순서는 [영상 불러오기 문서](docs/import-feature.md)에 있고, 서버 하나가 화면과 백엔드를 함께 제공하므로 `render.yaml` 하나로 Render 웹 서비스가 만들어집니다. 실제 AI Gateway 호출과 Render 배포는 아직 해 보지 못했습니다.

## 알려진 제한

- 현재 상황·원인 질문·연습 조건 시험·대본 자동 수정·필수 내용 보존·문장별 개선 확인은 없습니다. 군말에서 긴장을 자동 추정하거나 발생 원인·해결을 보장하지 않습니다.
- 현재 반복 표현은 같은 어절 반복 규칙이며 “음·어” 군말의 정밀 판별과 같은 기능이 아닙니다. 음성 인식이 군말을 빠뜨리거나 다르게 적을 수 있어 재생 확인·사용자 교정이 필요합니다.
- 속도는 인식된 한글 음절/분이고 전사 시각은 근사값입니다. 영어·숫자·인식 누락에서 한계가 있습니다.
- 현재 비교 조건은 목표 시간과 구간 계획입니다. 대본·분석 버전·허용 오차를 포함하는 비교는 개발 예정입니다.
- 긴 침묵·반복은 검토 후보이며 반드시 잘못된 발표라는 판정이 아닙니다.
- 실제 장치·저장 오류·삭제 오류·배포 검증은 [검증 계획](docs/validation-plan.md)에 남겨 두었습니다.
